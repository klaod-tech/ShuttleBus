# 02 · 정류장별 가까운 예정 버스 2개

## 목적

출발지·도착지를 모두 고르기 전에도 정류장 하나를 눌러 다음 버스를 확인할 수 있게 한다. 현재 선택 노선·날짜를 기준으로 해당 정류장의 예정 방문을 최대 2개 표시한다. 전체 노선 통합 조회는 별도 확정 전 포함하지 않는다.

이는 목적지까지 탈 수 있는 버스를 추천하는 기존 11의 검색과 다르다. 정류장 방문 예정 정보이며 승차 가능 보장이 아니다. 하차 전용 또는 승차 정책 미확인 방문에는 안내를 붙인다.

## 카드 구성

- 정류장 이름.
- 각 예정 버스의 방향·행선지.
- 시각 또는 남은 시간.
- 도착 예상 / 출발 예정 / 통과 예상 / 시간표 기준의 구분.
- 확인 필요 사유와 마지막 갱신 상태.
- ‘여기서 출발’, ‘여기로 도착’ 버튼 제안.

같은 정류장을 한 회차에서 두 번 방문하면 방문 방향을 구분한다. 같은 시각의 차량 두 대도 독립 슬롯으로 유지하며 한 대로 합치지 않는다.

## 시간 표시

합의: 1시간 미만은 상대 시간, 1시간 이상은 24시간제 HH:mm으로 표시한다. 날짜가 오늘과 다르면 날짜도 함께 표시하고 시각 중심으로 제공하는 것을 제안한다.

| 현재 시각 | 예정 시각 | 기본 표시 |
|---|---|---|
| 12:00 | 13:00 | 13:00 |
| 12:00 | 15:00 | 15:00 |
| 12:20 | 13:00 | 40분 뒤 |
| 12:50 | 13:00 | 10분 뒤 |

남은 시간이 0초보다 크고 1분 미만이면 ‘1분 이내’로 표시하는 방식을 제안한다. 분 단위 내림·올림은 아직 미확정이며 화면 설계 시 정한다. 1시간 구분은 반올림한 분이 아니라 실제 남은 시간으로 판단한다. 59분대와 1분 경계의 문구도 함께 확정한다.

0 이하가 되었다는 이유로 ‘도착’이나 ‘통과 완료’를 만들지 않는다. 예정 통과 시각이 지났지만 실제 통과가 확인되지 않았다면 ‘통과 여부 확인 중’으로 표시한다. 도착·출발도 해당 사건에 맞는 확인 문구를 사용한다. 실제 도착 관측이 신선하면 ‘도착 확인’으로 별도 표시할 수 있다.

## 정보 근거에 따른 문구

| 근거 | 예시 |
|---|---|
| 유효 도착 예측 | 10분 뒤 도착 예상 |
| 유효 출발 예측 | 10분 뒤 출발 예상 |
| 유효 통과 예측 | 10분 뒤 통과 예상 |
| 확인된 공시 시각 | 13:00 · 시간표 기준 |
| 1시간 미만의 확인된 공시 시각 | 40분 뒤 · 시간표 기준 |
| 사건 종류 미확정 공시값 | 시간표 13:00 · 도착/출발 확인 필요 |
| 오래되거나 신뢰할 수 없는 위치 | 위치 확인 중 |

출발·통과 시각을 ‘도착’으로 바꿔 부르지 않는다. 위치 재확인·만료 등 반대 근거가 있을 때 미래 시간표로 정상 실시간 안내를 되살리지 않는다.

## 선택과 정렬 제안

서버가 해당 정류장의 미래 예정 방문을 조회하고 방향·방문·차량을 구분해 정렬하는 방식을 제안한다.  유효 예측을 우선 근거로 선택하고, 허용되는 경우 확인된 공시 시각을 사용한다. 서로 다른 출처의 행도 선택한 시각 순으로 비교한다.

완료·취소 차량과 이미 출발·통과한 방문은 미래 예정 목록에서 제외한다. 미확인 항목을 억지로 정상 2개에 채우지 않는다. 정상 미래 항목은 최대 2개이며 현재 도착 확인·과거 통과 미확인 항목은 별도 상태 영역을 제안한다.

1개만 있으면 1개만 표시한다. 0개일 때는 남은 운행 없음, 해당 정류장 방문 없음, 시간표 미확인, 운행 없음 등을 구분한다. 미확인 항목이 남아 있으면 ‘모든 버스 종료’라고 표시하지 않는다.

서로 다른 방향을 통합해 2개를 보여줄지, 방향 선택 후 2개를 보여줄지는 화면 설계에서 확정할 항목이다. 초기 제안은 가까운 2개를 표시하되 각 행에 방향을 명시하는 방식이다.

## 갱신

화면의 남은 시간은 서버 기준 시각과 경과 시간으로 계산한다. 초 단위 숫자를 노출할 필요는 없다. 기준 시각·정보 유효기간은 서버 응답을 따른다. 앱 복귀·재연결·노선/날짜/정류장 변경 시 재조회하며 늦게 도착한 이전 응답이 새 선택을 덮지 않게 한다.

주기 조회는 기존 30초 제안을 출발점으로 서버와 협의한다. 이벤트 연동 전에도 조회 방식으로 기능할 수 있어야 한다. 연결이 끊기면 마지막 갱신 정보를 표시하고 만료된 예측을 계속 정상 표시하지 않는다.



## 같은 버스의 중복 표시 방지

목록의 한 항목은 차량 슬롯과 해당 방문의 조합이다. 같은 방문의 도착·출발 시각을 각각 별도 버스로 세지 않는다. 신선한 도착 확인 항목을 별도로 표시했다면 같은 방문의 예상 출발은 그 항목에 보조 표시하고 미래 2개에 다시 넣지 않는다. 이후의 다른 방문과 다른 차량 슬롯은 별개다.

정류장 조회의 대표 시각은 새 서버 계약에서 확정한다. 초안은 선택한 정보 출처 안에서 도착→통과→출발 순으로 대표 시각을 고르고 출발만 있으면 ‘출발 예정’으로 명시하는 방식이다. 기존 ../md/11-boarding-candidates.md의 출발 우선 정렬은 승차 후보 검색용이므로 그대로 바꾸거나 정류장 도착 안내에 무조건 재사용하지 않는다. 이 차이는 구현 전 서버 담당자와 합의해야 한다.

사건 종류가 미확정인 공시 시각만 있으면 정상 미래 2개에 포함하지 않고 참고 시간표에 둔다. 확인 필요 항목은 최대 2개 규칙과 별도이며, 카드가 길어지면 요약과 펼치기로 제공하는 것을 제안한다. ‘2개’는 정상 미래 예정 항목의 상한이며 모든 상태를 합친 카드 총행 수의 상한은 아니다.

## 다른 날짜와 자정

오늘이 아닌 미래 날짜는 해당 운행일의 첫 예정 방문부터 최대 2개를 시각으로 보여주는 것을 제안한다. 현재 시각의 시·분을 그 날짜에 복사해 필터링하지 않는다. 과거 날짜는 ‘다음 버스’ 대신 시간표 열람으로 연결한다. 미래 날짜의 조기 완료·취소 등은 서버 상태를 따른다.

서울 날짜를 기준으로 표시하며, 오늘 운행이 자정을 넘어가면 ‘다음 날 00:10’처럼 실제 예정 날짜를 밝힌다. 운행일과 사건 날짜를 혼동하지 않는다. 자정에 앱이 열려 있을 때 선택 날짜를 자동으로 바꾸지 않고 ‘오늘 보기’를 제공하는 것을 제안한다.
