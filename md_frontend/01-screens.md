# 01 · 화면 구성

## 채택한 화면 방향 (2026-09-18)

Transit 앱의 지도·하단 카드와 Transit PC의 지도·옆 패널을 참고한다. Citymapper의 경로 비교 구성은 사용하지 않는다. 모바일을 기본으로 하며 넓은 화면에서는 상세 내용을 지도 왼쪽 패널로 옮긴다. 색상·아이콘 등은 자체 디자인으로 구현한다.

## 첫 화면 — 지도

앱 진입 시 지도 화면을 기본으로 연다. 날짜·시각은 **`지금 출발 ▾` 칩** 하나로 고른다 — 기본은 지금, 누르면 날짜(오늘부터)와 출발 시각(5분 단위)을 고르는 시트. 과거 날짜와 오늘의 지난 시각은 고를 수 없고 도착 기준은 없다 (2026-09-30, [출발 시각 계획](../md/PLAN-departure-time.md) 2장). 정거장 카드와 출발·도착 검색이 같은 칩 값을 쓴다. 최초 선택 노선은 천안아산역 노선이다 (2026-09-15 확정). 현재 범위는 선택 노선 안의 조회다.

위에서 아래로 다음 요소를 배치한다.

1. 왼쪽 위 햄버거 메뉴(☰), 선택 노선, `지금 출발 ▾` 칩. 큰 검색창은 기본 지도에 상시 노출하지 않는다.
2. 지도와 확인된 정류장 마커.
3. 선택 상태에 따른 하단 카드.

정류장을 선택하지 않은 상태에서는 ‘정류장을 누르거나 출발지와 도착지를 선택하세요.’라는 안내를 표시한다.

정류장 좌표가 미확정이면 마커를 만들지 않고 목록에서 확인 필요로 표시한다. 같은 물리 정류장은 마커 하나로 표현하며 방향·반복 방문은 상세에서 구분한다. 지도 실패 시 정류장 목록과 시간표 조회를 유지한다. 지도 열람 자체에 학생 위치 권한을 요구하지 않는다.

수동 수집 단계는 마지막 확인 정류장과 확인 시각을 표시한다. 정류장 사이를 움직이는 가상 버스는 그리지 않는다. GPS 단계의 차량 마커는 검증된 실제 좌표와 측정 시각을 사용한다.

## 정류장 선택

마커 또는 목록 항목을 누르면 선택 강조와 정류장 카드가 열린다. 카드에는 이름, 방향, 가까운 예정 버스 최대 2개, 정보 기준, 필요한 승차 안내를 표시한다. 상세 규칙은 02를 따른다.

‘여기서 출발’ 또는 ‘여기로 도착’을 누르면 해당 검색 칸에 정류장을 넣는다. 반대쪽이 비어 있으면 선택을 이어가고, 두 곳이 채워지면 경로에 맞는 탑승 후보를 조회한다. 닫기/뒤로는 직전 화면으로 돌아가며, 지도 기본 상태에서 연 카드만 지도 기본으로 돌아간다.

## 출발지·도착지 선택

왼쪽 메뉴의 ‘검색’ 또는 정류장 카드의 출발·도착 지정 버튼으로 선택 화면을 연다. 출발지와 도착지 입력칸, 두 값 교환 버튼, 선택 노선의 정류장 목록을 둔다. 글자를 입력하면 정류장 이름을 필터링한다. 일반 주소·장소 검색은 현재 범위가 아니다.

일반 지도 탐색 중 마커 클릭은 정류장 카드만 연다. 출발지 또는 도착지 지정 모드에서 지도 선택을 요청했을 때만 해당 입력칸을 채운다. 마커를 둘러보는 동작이 기존 검색 조건을 몰래 바꾸지 않게 한다. 지도 선택과 목록 선택은 같은 값을 사용한다. 사용자가 방문 순번을 입력하게 하지 않는다. 서버가 같은 회차 안에서 출발 이후 도착하는 방문 쌍을 찾는다. 다른 노선으로 자동 전환하거나 환승 경로를 만들지 않는다.

## 검색 결과와 차량 상세

검색 결과에는 승차·하차 정류장, 방향, 승차 예정, 목적지 예정 또는 확인 필요, 시간표/예측 구분을 표시한다. 추천 가능 후보와 확인 필요 후보를 구분한다. 사용자가 선택한 버스를 새 추천으로 자동 교체하지 않는다.

차량 상세에는 방문 순서, 선택 승하차 지점, 마지막 확인 정보, 예정 시각과 공지·운행 상태를 표시한다. 도착만 확인된 버스를 이미 떠난 버스로 표시하지 않는다.

## 왼쪽 메뉴와 프로필

왼쪽 위 햄버거 메뉴(☰)를 누르면 왼쪽 패널을 연다. 닫기 버튼·패널 밖 선택·Escape로 닫는다. 키보드 접근 시 포커스가 패널 안에 유지되고 닫은 뒤 원래 버튼으로 돌아오도록 구현 시 확인한다. 메뉴가 열리면 뒤의 지도·상세 패널은 조작되지 않게 한다.

| 메뉴 | 내용 | 상태 |
|---|---|---|
| 검색 | 출발·도착 정류장 선택 | 합의 |
| 시간표 | 노선·날짜별 공시 시간표 | 합의 |
| 맨 아래 프로필 이미지 | 클릭하면 프로필 설정 | 합의 |

프로필은 메뉴 맨 아래에 이미지 버튼만 표시한다. 기본 아바타를 제공하고 접근 가능한 이름은 ‘프로필 설정’으로 지정한다. 설정에서 닫기/뒤로를 누르면 직전 화면으로 복귀한다. 학생 로그인 없이 기기 내 프로필 이미지와 화면 설정을 저장하는 방식을 초기 구현 기준으로 삼는다. 상세 설정 항목은 구현 시 정리하며 기기 간 동기화·학생 계정 API는 현재 범위에 포함하지 않는다. **학생 화면에는 로그인 입구가 없다** — 담당자 로그인은 별도 앱에서만 한다 (아래 '담당자 화면은 별도 앱').

메뉴 항목은 검색·시간표로 간소화한다. 이용 안내는 정류장·차량 상세에, 유효 공지는 배너에 제공하며 독립 메뉴는 추가하지 않는다. 입력자·관리자 화면은 학생 화면과 별도 앱이다 (아래). 즐겨찾기·내 위치·환승 검색은 이번 초안에 추가하지 않는다.

## 담당자 화면은 별도 앱 (2026-09-30 결정)

입력자·관리자 화면은 학생 앱과 **다른 프로젝트·다른 주소·다른 디자인**으로 만든다. 학생 앱 어디에서도 링크하지 않고 검색 엔진에 노출하지 않는다(noindex). 둘 다 같은 서버 API(`/api/v1`)를 쓴다 — 서버를 나누는 것이 아니다.

**왜.** 학생 화면 설정에 담당자 로그인이 있으면 궁금한 학생들이 눌러 본다. 한두 명이면 괜찮지만 많은 사람이 시도하면 두 가지가 문제다.

| 위험 | 이유 |
|---|---|
| 서버가 느려진다 | 로그인은 비밀번호를 일부러 무거운 계산(scrypt)으로 확인한다. 없는 아이디도 같은 계산을 한다(시간 차로 아이디 존재를 알리지 않기 위해). 동시에 몰리면 같은 프로세스의 학생 조회까지 느려진다 |
| 담당자가 잠긴다 | 5회 실패 15분 잠금이 **계정 기준**이다(`01` 5장). `admin`처럼 짐작 가능한 아이디는 남이 틀려도 진짜 담당자가 잠긴다. 운행 중 입력자가 잠기면 도착 입력이 멈춘다 |

화면 분리는 **궁금해서 누르는 사람**을 없앤다. 일부러 두드리는 사람은 막지 못한다 — 주소는 퍼질 수 있고 API는 직접 부를 수 있다. 그 대비는 외부 공개 전에 서버에서 한다 (SB-0105: IP당 로그인 시도 제한, 짐작하기 어려운 담당자 아이디). 개발 중에는 시험하다 막히면 불편하므로 넣지 않는다 (2026-09-30 사용자).

**나눠서 좋은 점.** 학생 앱은 지도 조회, 입력자 앱은 버스 안에서 큰 버튼으로 빠르게 누르고 끊겨도 폰에 쌓아 두는 화면(`md/06`), 관리자 앱은 취소·공지·검토 업무 화면이다. 쓰는 방식이 달라 한 앱에 섞으면 셋 다 어중간하다. 입력자는 담당자 앱만 폰 홈 화면에 둔다.

**준비할 것.**
- 담당자 앱의 출처(예: `http://localhost:3001`)를 서버 `CORS_ORIGINS`에 쉼표로 더한다 (must_do S2).
- 할 일 목록은 [must_do](must_do.md) 3장(입력자)·4장(관리자). 입력자·관리자를 한 앱의 두 영역으로 둘지, 앱 이름·폴더는 화면 담당이 정한다.
- 디자인은 학생 앱과 따로 한다 ([05](05-design-notes.md)).

## 시간표

노선과 날짜를 선택하고 해당 날짜의 실제 회차를 표시한다. 공시 시각을 실시간 예측으로 덮어쓰지 않는다. 주말·공휴일 예외, 2대 운행, 기점이 다른 회차, 학생회관 해당 안내를 구분한다.

운행 없음, 자료 확인 필요, 적용 기간 밖은 서로 다른 상태로 표시한다. 빈 화면만 보고 ‘오늘 운행 종료’라고 단정하지 않는다.

## 이용 안내

확인된 실제 승차 위치와 학생회관 적용 회차를 안내한다. 공대 승차장 대체인지 추가인지 미확정인 사항은 확인 필요로 둔다. 손들기·하차벨·결제 안내는 기존 문서의 확인된 내용만 사용한다. 앱에서 정류장을 선택하는 것이 기사에게 승차 요청을 보내는 기능은 아니다.


## 화면 전환과 선택 유지

- 정류장 카드와 검색 결과·차량 상세가 하단에서 겹쳐 열리지 않도록 주 패널은 하나만 표시한다. 닫기/뒤로는 직전 화면으로 돌아가며, 기본 지도에서 연 카드만 지도 기본으로 돌아간다.
- 출발·도착 선택 화면은 임시 편집값을 사용한다. 적용하면 후보를 재조회하고 취소하면 기존 검색으로 돌아간다. 두 값 교환도 적용 시 방문 순서를 다시 검증한다.
- 메뉴를 닫는 것만으로 노선·날짜·검색을 초기화하지 않는다. 지도와 시간표는 같은 선택 노선·날짜를 공유한다.
- 노선·날짜 변경 시 이전 후보·선택 차량·정류장 카드·구독을 정리한다. 출발·도착은 새 목록에서 유효성을 재확인하며 더 이상 존재하지 않는 선택은 지우고 안내한다.
- 검색 적용으로 출발·도착이 바뀌면 기존 선택 차량을 해제하고 재조회한다. 단순 서버 갱신은 사용자 선택을 자동 교체하지 않는다.
- 요청 실패는 ‘버스 없음’과 구분하고 재시도 동작을 제공한다. 마지막 결과를 남기는 경우 과거 정보임을 표시한다.

## 공지 표시 범위

노선 공지는 노선 선택 후, 특정 회차 공지는 해당 회차를 선택했을 때 표시한다. 공지 목록 메뉴를 추가해도 별도 공지 원본을 만들지 않고 같은 자료를 사용한다. 현재 GET /notices는 trip_id를 생략하면 그 노선의 모든 회차 공지까지 반환하므로, 메인 배너는 trip_id가 null인 노선 공지만 골라 표시한다. 회차 선택 시에는 해당 trip_id로 다시 조회한다. 만료된 배너는 제거하며 ‘취소’ 공지 문구만으로 차량 상태를 취소로 바꾸지 않는다.
