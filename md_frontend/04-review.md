# 04 · 문서·화면 연동 점검

점검일: 2026-09-18. 프로젝트 Markdown 27개와 관련 API·상태 응답·인증·실시간·재전송 코드를 대조했다. 외부 패키지 문서는 범위 밖이다. 이 문서는 점검 결과이며 화면 구현이나 전체 서버 무결성을 보증하지 않는다.

## 반영 완료

- README·01·02의 끊긴 문장 복구. 분 단위 내림·올림은 미확정으로 통일했다.
- 최초 노선을 천안아산역으로 통일하고 기준 문서 버전을 최신 변경 기록에 맞췄다.
- 현재 개발 로그인은 관리자 admin/admin, 입력자 user/1234, 아이디·비밀번호 방식이다. 학생은 로그인하지 않는다. 대체 로그인 방식 논의가 개발을 막지 않는다.
- 피그마 사용을 필수 조건에서 제외했다. 화면 범위·배치 합의는 여전히 필요하다.
- 재전송은 동일 본문·동일 키 유지, 본문 변경 시 새 키 발급으로 정리했다. 구체적 절차는 [수집 계약 5장](../md/06-manual-collection.md)이 소유한다.
- 카드 닫기 경로, 노선 공지 배너 필터, 로그인·시계 확인의 요청 키 예외를 명시했다.
- 회차 취소 시 이미 완료된 차량은 완료 상태를 보존한다는 본문·검증 기준을 실제 코드 및 운영 구현 메모와 맞췄다.

## 남은 문제와 처리 방향

| 우선 | 항목 | 코드·문서에서 확인한 사실 | 다음 처리 |
|---|---|---|---|
| 높음 | 정류장별 다음 버스 조회 | 현재 scheduled-trips는 출발·도착 쌍 또는 전체 회차만 지원한다 | 02·03에 남은 정렬·날짜·확인 항목 계약을 합의하고 서버에서 구현. 외부 버스 API와 별개의 기능 |

| 높음 | 실측 이력 표시 부족 | VisitOut에는 방문별 실제 도착·출발·통과 시각이 없고, last_observation은 차량의 마지막 기록 하나다. already_passed·trip_completed 경로는 basis_observation도 비울 수 있다 | 학생 상세의 지난 기록에 실제 시각을 표시하려면 공개 응답 보완 필요. 다른 방문의 마지막 기록을 대신 쓰지 않음 |

## 외부 API와 현재 서버

사용자는 외부 버스 API를 아직 문의하지 않았고 확보하지 않았다고 확인했다. 현재 서버는 저장된 시간표와 자체 관측을 제공한다. 외부 API가 확보되었다고 가정하거나 외부 실시간 위치를 표시하지 않는다. 지도 SDK도 버스 운행 데이터를 제공하는 API와 다르다.

## 화면 호환성 검증 계획

앱 미구현 상태이므로 아래는 통과 결과가 아니라 구현 후 점검 목록이다.

- 작은 휴대폰부터 태블릿·PC까지 폭 변경, 가로·세로 전환, 긴 정류장 이름과 큰 글씨에서도 버튼·본문 잘림 확인.
- 모바일 주소창 높이 변화·하단 안전 영역·소프트 키보드가 검색과 하단 카드를 가리지 않는지 확인.
- iOS Safari·Android Chrome·PC Chrome/Edge에서 지도 표시, 선택, 스크롤, 뒤로 이동, 로그인·큐 복구 확인. 실제 기기 미확인 항목은 에뮬레이션 결과와 구분.
- 키보드 접근, 메뉴 포커스 유지·복귀, 색상 이외 상태 문구, 지도 없이 목록만으로 검색 가능한지 확인.
- 느린 통신·응답 순서 뒤집힘·재연결·백그라운드 복귀·자정·공지 만료 확인.
- 수집 화면의 영속 저장 실패·다중 탭·401·재시도 소진·새로고침·결과 유실 후 복구 확인.

## 점검 한계

문서와 관련 소스의 정적 점검을 수행했다. 화면은 아직 없어 실제 기기 호환성을 검증할 수 없다. 이번 세션에서 API 가상환경 Python 실행이 프로세스 생성 오류로 실패해 서버 시험은 재실행하지 못했다. ROADMAP의 178개 통과는 이전 기록이며 이번 결과가 아니다. 서버·계정 데이터는 변경하지 않았다.
