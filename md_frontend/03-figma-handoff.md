# 03 · 화면 설계와 서버 연동 준비

## 화면 도안 제작 순서

1. 지도 기본: 왼쪽 위 햄버거 메뉴·노선/날짜, 정류장 마커, 하단 안내.
2. 정류장 선택: 방향과 예정 버스 2개, 시간표/예측 구분, 출발/도착 지정 버튼.
3. 출발·도착 선택: 입력칸, 교환, 정류장 목록, 검색 결과 없음.
4. 탑승 후보: 추천 가능·확인 필요, 선택 차량 상세로 이동.
5. 차량 상세: 방문 순서, 마지막 확인, 승하차 지점, 공지.
6. 시간표: 노선·날짜, 회차, 예외 안내.
7. 왼쪽 메뉴: 검색·시간표와 하단 프로필 이미지, 열림·닫힘과 포커스 복귀.
8. 프로필 설정: 기본 아바타·이미지 변경·기기 내 설정·담당자 로그인. 이용 안내는 상세 화면에 포함.

우선 휴대폰 화면 크기 하나로 흐름을 만든 뒤 넓은 화면의 지도·상세 패널 배치를 정한다. 기본 배치는 Transit 앱·PC 조합으로 합의했다. 세부 크기·색상·글꼴은 구현 초안을 보며 조정한다.

## 상태별 도안

| 대상 | 준비할 상태 |
|---|---|
| 지도 | 로딩, 정상, 실패 후 목록 |
| 정류장 카드 | 미래 버스 2개/1개/0개, 현재 도착 확인, 통과 미확인 |
| 정보 품질 | 실시간 예측, 시간표만 있음, 위치 확인 중, 연결 끊김 |
| 날짜 | 정상 운행, 운행 없음, 자료 미확인, 기간 밖 |
| 검색 | 선택 전, 한쪽 선택, 양쪽 선택, 결과 없음, 확인 필요 후보 |
| 차량 | 도착 확인, 출발/통과, 완료, 취소 |

색상만으로 상태를 구분하지 않고 문구를 함께 둔다. 메뉴·카드·검색창의 닫기와 뒤로 이동 경로를 연결한다. 지도 위 조작 버튼과 카드가 서로 가리지 않도록 확인한다.

## 서버 담당자와 합의할 추가 계약

정류장 하나의 다음 버스 조회는 새 요구다. 기존 GET /scheduled-trips는 출발·도착을 모두 주거나 모두 생략하는 계약이며 하나만 전달하면 오류다. 그 API에 출발지만 넣어 동작한다고 가정하지 않는다. 새 조회 또는 기존 API 확장은 담당 문서에 먼저 반영한 뒤 구현한다.

필요한 의미 정보는 다음과 같다. 필드 이름과 URL은 아직 확정하지 않는다.

- 선택 노선·운행 날짜·물리 정류장.
- 차량 슬롯·회차·방문 식별자, 방향·행선지.
- 방문별 예측 또는 공시 시각, 사건 종류, 정보 근거.
- 방문 상태·완료/취소 상태·승차 정책·확인 필요 사유.
- 최대 2개 미래 항목과 별도 확인 항목의 분류 및 결정적인 정렬.
- 서버 기준 시각·갱신 주기·정보 유효기간·조회 결과 없음의 사유.

원래 출발·도착 후보 검색과 이 정류장 조회는 역할을 분리한다. 기존 상태·예측의 의미는 ../md/03-state-contract.md와 ../md/08-prediction.md를 재사용하며 프론트가 시간표에서 임의 ETA를 계산하지 않는다.

## 구현 시작 조건

기본 화면 범위와 배치는 합의되었으므로 프론트 기본 구조와 준비된 API의 화면 구현을 시작할 수 있다. 정류장 다음 버스 등 미완료 기능은 계약 확정 후 연동한다. 문서의 API 이름만으로 서버가 작동한다고 판단하지 않는다. 구현 시 실제 정상·오류·빈 결과 응답을 받아 화면 흐름을 확인한다.

피그마 사용은 필수가 아니다. 다른 도구의 도안이나 합의한 화면 구상도 사용할 수 있다. 별도 사용자 도안은 필요하지 않다. 미확보 실시간 데이터는 실제 정보처럼 표시하지 않는다.

## 도안 검토 항목

- 12시 조회에 13시·15시, 12시 20분 조회에 40분 뒤·15시가 보이는가.
- 도착 예상과 시간표, 출발·통과가 구분되는가.
- 같은 정류장의 방향과 반복 방문을 구분할 수 있는가.
- 지도 실패에도 정류장 목록으로 진행 가능한가.
- 미확인 정보를 운행 종료나 도착 완료로 단정하지 않는가.
- 정류장 카드에서 출발·도착 검색으로 이어지는가.
- 미래 버스가 2개 미만이거나 운행이 없는 경우도 그려져 있는가.

## 추가 대조 사례

- 같은 차량·방문의 도착과 출발이 동시에 있어도 버스 2대로 표시하지 않는다.
- 도착 확인된 방문의 예상 출발은 보조 표시이며 미래 목록에 중복하지 않는다.
- 60분·59분 59초·1분·1분 미만·0초를 구분한다. 세부 표시는 02를 따른다.
- 내일 조회와 자정 이후 예정에 날짜가 정확히 보인다.
- 검색 결과를 보다가 마커를 둘러봐도 출발·도착이 자동 변경되지 않는다.
- 메뉴 닫기와 화면 이동 시 선택 유지, 노선 변경 시 이전 결과 제거가 구분된다.
- 조회 실패·버스 없음·시간표 미확인이 서로 다르게 보인다.
