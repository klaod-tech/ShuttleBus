# GPS 공백 복구 — 자료가 오기 전에 준비해 둘 설계

- 분야: 서버
- 작업: SB-0081

2026-09-30 작성. **실제 셔틀 GPX가 들어오자마자 적용할 수 있도록** 복구 흐름을 기존 설계와 [논문 기록](논문.md)의 방법에 연결해 둔다. 이 문서는 새 계약을 만들지 않는다 — 규칙의 정본은 `02`·`03`·`07`·`08`이고 바꾸려면 자료를 본 뒤 승인받는다 (CLAUDE.md 2장). 값(임계값)은 여기서도 정하지 않는다. 무엇을 재서 정할지만 적는다.

왜 지금 구현하지 않나: 실측 경로·좌표가 없고([IMPROVEMENTS](IMPROVEMENTS.md) '적용 게이트'), 실시간 GPS 수신은 P6 단계라 실측 표본·설치 허가가 있어야 착수한다 (CLAUDE.md 7장).

## 1. 무엇을 복구하나

GPS가 끊긴 사이 버스가 정거장을 지나면, 좌표가 돌아와도 그 방문이 '도착 전'으로 남는다. 복구는 **좌표가 돌아온 뒤** 그 사이 지나간 방문을 다시 판별하고 위치·예측을 정상으로 되돌리는 일이다.

원칙 세 가지 (모두 이미 정해져 있다):

- **관측하지 않은 이동을 만들지 않는다.** 공백 동안의 위치를 채워 그리지 않는다 (`07` 9장, `10`).
- **통과 여부 복원과 통과 시각 복원은 다르다.** 지나갔다는 근거가 있어도 시각 근거가 없으면 시각은 null로 둔다 (`02` 4장 `inferred`).
- **틀린 확정은 보류보다 나쁘다.** 애매하면 추가 좌표를 기다리고 '위치 확인 중'을 유지한다.

## 2. 복구 흐름 6단계 — 방법과 근거

[IMPROVEMENTS](IMPROVEMENTS.md) '검토할 복구 흐름'의 6단계에 방법을 붙인다. `07` 6장의 설정 이름을 그대로 쓴다 — 새 설정이 필요하면 '새 설정 후보'로 표시했다.

| 단계 | 하는 일 | 방법 | 근거 | 정해야 할 값 |
|---|---|---|---|---|
| 1. 보존 | 마지막 유효 좌표·측정 시각·수신 시각·회차·방문 순서를 남긴다 | 원시 좌표는 도착 순서 그대로 저장 (`07` 2장) | 기존 설계 | 없음 |
| 2. 중단 감지와 구분 | 좌표가 끊겼음을 알고, **통신 중단**인지 **측정 실패**인지 가른다 | 좌표 나이가 `gps_stale_after_seconds`를 넘으면 locating. 복귀 뒤 `measured_at`이 과거인 좌표가 몰려 오면 통신 중단(단말이 쌓아 둠), 재전송 뒤에도 측정 시각에 빈 곳이 남으면 측정 실패 | 기존 설계 (`03`, `07` 5장). [논문 기록](논문.md) 4장 '통신만 중단' | `gps_stale_after_seconds` (시험값 90) |
| 3. 재전송 좌표 검증 | 중복·순서·정확도·튀는 점을 거른다 | `measured_at` 순 재정렬 뒤, 직전 유효 좌표에서 **등속으로 예측한 위치**와 실제 좌표의 차이(잔차)가 크면 그 점을 판정에서 뺀다. 원본은 보존. 복귀 첫 점을 무조건 믿지 않는다 | **P3** (예측과 관측의 차이로 이상 관측을 걸러내는 강건 추정)를 좌표 수준에 옮긴 것 — 논문 방법의 직접 구현이 아니다 | `max_position_accuracy_m`, `max_plausible_speed_mps`, 새 설정 후보: 잔차 한도 |
| 4. 진행 위치 재판별 | 돌아온 좌표가 노선의 **어디쯤**인지 | 좌표를 검증된 경로 폴리라인에 투영해 경로 위 누적 거리를 구한다. 방향은 누적 거리가 늘어나는 쪽만 인정. 경로 밖이면 `07` 경로 이탈 관문이 막는다 | 기존 설계 (`07` 4장 '경로 이탈 게이트') | `max_route_deviation_m`, `route_deviation_min_points`, `route_rejoin_min_points` |
| 5. 누락 방문 복원 | 공백 사이 지나간 정거장을 판별한다 | 공백이 `max_interpolation_gap_seconds` 이하면 복원이 아니라 `07` 4장 정상 판정이다 — 공백 양끝 좌표 선분이 정거장을 지나면 `passed`, 시각은 `interpolated`. 그보다 긴 공백은 아래 3장 조건을 **모두** 만족할 때만 `passed_inferred` — 지나갔다는 사실만 있고 **시각은 만들지 않는다** | 기존 값 (`02` 4장 time_confidence, `02` 방문 상태 `passed_inferred` 정의). 새 상태를 만들지 않는다 | `max_interpolation_gap_seconds` |
| 6. 상태·예측 갱신 | 위치 배지·방문·예측·후보를 한 번에 맞춘다 | 연속 좌표 `route_rejoin_min_points`개가 경로 위면 current로 복귀. 예측은 **정거장 관측으로 보정**하는 현행 방식을 그대로 쓰고, `interpolated`는 예측에 쓰되 통계 학습에서는 뺀다 | **P5** (새 관측으로 누적 예측 오차 보정). **P4**(비선형 갱신)는 반복 운행 자료가 쌓인 뒤 비교 후보 | 없음 (기존 `08`) |

**쓰지 않기로 한 것 (2026-09-22 판단 유지):** IMU로 공백 동안 위치를 추정하는 것(**P2**)은 첫 구성에서 빼고, 공백이 실제로 문제로 확인되면 검토한다. 신호 정보(**P1**)는 공급원을 확보하지 못하면 쓰지 않고 교차로 지연을 실측으로 학습한다.

## 3. 누락 방문을 복원해도 되는 조건

5단계에서 정거장 S를 '지나갔다'고 보려면 아래가 **모두** 참이어야 한다. 하나라도 아니면 복원하지 않고 추가 좌표를 기다린다.

1. 공백 **앞** 마지막 유효 위치가 경로상 S보다 앞이고, 공백 **뒤** 안정된 위치(연속 `route_rejoin_min_points`개)가 S보다 뒤다.
2. 그 사이 경로 구간이 모두 `verified`이고 `path_source`가 `manual_trace`가 아니다 (`07` 4장 마지막 문단).
3. 공백 동안의 평균 속도(경로 거리 ÷ 공백 시간)가 그럴듯한 범위다 — 너무 빠르면 좌표가 틀렸고, 너무 느리면 우회·정차 가능성이 있다.
4. 왕복·순환 노선에서 S가 두 번 나오면 **방문 순서(`trip_stop_id`)** 로 어느 방문인지 정해진다. 정할 수 없으면 복원하지 않는다.
5. 수동 기록과 겹치면 `02`의 비교 정책을 따른다 — 비교 단계(`manual_reference`)에서는 수동이 공개 대표이고 GPS 복원은 비교 원본으로만 남는다. 복원이 정책을 건너뛰지 않는다.

예: 학교 → A → B → C에서 A 직후 끊겼다가 B와 C 사이에서 돌아오면, 위 조건이 맞을 때 B만 `passed_inferred`(시각 없음). 현재 좌표가 B와 가깝다는 것이나 예정 시각이 지났다는 것만으로는 확정하지 않는다 ([IMPROVEMENTS](IMPROVEMENTS.md) 예시와 같다).

## 4. 자료 없이 검증하는 방법 — 합성 공백 시험

실제 셔틀 자료가 오기 전과 온 뒤 모두 쓴다. 결과는 **합성 장애 시험**으로 표시하고 실제 불량 구간 시험과 섞지 않는다 ([논문 기록](논문.md) 5장).

1. 끊김 없는 트랙에서 구간을 일부러 가린다 (공백 길이 10초·30초·60초·180초, 정거장 앞·위·뒤).
2. 복구 흐름을 돌려 가린 구간의 방문을 판별한다.
3. **정답**은 탑승 중 수동 기록(정거장 도착·출발)이다. 가리기 전 트랙의 판별 결과는 참고로만 본다 — 입력과 같은 GPS라 정답으로 쓰지 않는다.
4. 비교 기준선은 **현행 동작**(복원하지 않고 '위치 확인 중' 유지)이다.

| 지표 | 목표 |
|---|---|
| 잘못 복원한 방문 (지나가지 않았는데 passed_inferred) | **0건** — 이게 있으면 그 조건 값으로는 켜지 않는다 |
| 맞게 복원한 방문 비율 | 기준선(0%)보다 높을수록 좋다 |
| 보류한 방문 | 허용. 틀린 확정보다 낫다 |
| 복귀 후 current까지 걸린 시간 | 짧을수록 좋다 |
| 예측 오차 (복원 전·후) | 복원 후가 나빠지면 안 된다 |

튀는 좌표 주입 시험(한 점을 수백 m 옮기기)도 같은 방식으로 3단계 거르기를 검사한다.

## 5. 녹화할 때 함께 남길 것 (SB-0075)

녹화 한 번으로 경로와 복구 값을 함께 정할 수 있게, 녹화 때 아래를 남긴다.

| 남길 것 | 방법 | 정해지는 값 |
|---|---|---|
| 같은 패턴 **2회 이상** 독립 녹화 | 다른 날 또는 다른 회차 | 두 번째는 경로 검증용 (`app.survey verify`). 두 트랙 사이 거리 분포 → `max_route_deviation_m` |
| 기록 간격 1초, 배터리 절약·앱 종료 끄기 | GPS Logger 설정 | 공백이 앱 탓인지 환경 탓인지 구분 |
| 정거장 도착·출발 시각 | GPS Logger 주석 또는 종이·다른 앱 메모 | **정답 자료.** 정차 시간 분포 → `dwell_min_seconds` |
| 신호가 끊긴 것 같은 곳 | 지하차도·건물 사이 등 위치와 시각 메모 | 실제 공백 위치 확인 |
| 우회·평소와 다른 길 | 메모 | 3장 조건 3의 근거 |
| 녹화 직후 점검 | `python -m app.survey inspect --file 파일.gpx` | 공백 수·길이 → `max_interpolation_gap_seconds`, 최고 속도 → `max_plausible_speed_mps` |

GPS Logger는 정확도(accuracy·hdop)를 내보내지 않는다 ([IMPROVEMENTS](IMPROVEMENTS.md) GPS Logger 후기). `max_position_accuracy_m`은 이 앱으로는 정할 수 없고, 실시간 단말을 고를 때(`SB-0083`) 확인한다.

## 6. 자료가 온 뒤 승인받을 것

| 바꿀 곳 | 내용 |
|---|---|
| `07` 5·6장 | 공백 복원을 켜는 조건(3장), 미정 설정값을 실측으로 채움 |
| `02` 4장 | GPS 복원이 만든 `passed_inferred`·`interpolated`의 출처 표시와 수동 기록 우선 |
| `03` | locating → current 복귀 규칙(연속 좌표 수) |
| `08` | 복원 관측을 예측 근거로 쓰는 범위 |
| `01` 설정 인덱스 | 새 설정 후보(잔차 한도) 등재 |

순서: 녹화 자료 적재·검증(SB-0075·SB-0078·SB-0079) → 합성 공백 시험으로 값 후보 비교 → 이 표의 계약 변경 승인 → P6 착수 승인 뒤 구현.
