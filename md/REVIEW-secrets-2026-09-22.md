## 결론

**실제 비밀값은 올라가지 않았다.** 걸린 것은 예시·시험용 문자열이다. 다만 개발 계정 비밀번호처럼
**실제로 동작하는 약한 자격증명이 문서에 적혀 있었으므로** 저장소에서 지웠다.

## 남은 조치 — 사용자

1. **개발 계정 비밀번호 재설정.** `admin`·`user`는 공개 저장소에 비밀번호가 적혀 있었으므로 더 이상 쓰지 않는다.
   ```powershell
   cd api
   .\.venv\Scripts\python.exe -m app.accounts create --username admin --role admin
   .\.venv\Scripts\python.exe -m app.accounts create --username user --role collector
   ```
   재설정하면 이전에 발급된 토큰도 즉시 무효가 된다 (`token_not_before`).
2. **`main` 갱신.** `develop`을 합치면 `main`의 `.env.example`에서도 값이 사라진다.
3. **GitGuardian 처리.** 경보 상세에서 파일·줄을 확인한 뒤, 위 내용과 맞으면 해결 처리한다.
   실제 비밀값이 아니었으므로 외부 서비스 키 교체는 필요 없다.

## 이력에 남는 것

이미 올라간 커밋에는 위 문자열이 그대로 남는다. **이력 재작성(force push)은 하지 않는다** —
값들이 로컬 개발용이고, 재설정으로 무력화되며, 재작성은 공동 작업자의 사본을 깨뜨린다.
실제 비밀값이 올라간 경우라면 판단이 달라진다.

## 재발 방지 규칙

- 비밀번호·키는 `.env`·`.env.local`에만 둔다. **문서·코드·커밋 메시지·채팅에 적지 않는다.**
- 예시 파일(`*.example`)은 키 이름과 주석만 둔다. 자리표시 값도 비밀값처럼 보이면 쓰지 않는다.
- 시험은 고정 비밀번호 문자열 대신 실행 시각에 만든 값을 쓴다.
- 이 규칙은 [작업 지침](../CLAUDE.md) 5절 '자료 원칙'에 이미 있다. 이번 항목은 그 적용 사례다.
