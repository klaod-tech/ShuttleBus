# 09 · 구간 통계

> 실제 관측에서 정거장 간 소요시간을 학습한다. 예측(`08`)이 이 값을 읽는다.
> 참조: [공통 규약](01-conventions.md) · [관측 계약](02-observation-contract.md)

배치로 돈다. 예측과 라이프사이클이 다르고, 인터페이스는 `travel_times` 테이블 하나다. **통계는 예측을 모른다.**

---

## 1. `travel_times`

| 열 | 설명 |
|---|---|
| `route_version_id` | 노선 버전 |
| `from_route_stop_id` | 구간 시작 방문 |
| `to_route_stop_id` | 구간 종료 방문 |
| `from_event_type` | 시작 이벤트 종류 |
| `to_event_type` | 종료 이벤트 종류 |
| `time_band_id` | effective_day_type으로 구분된 시간대. 08 §3의 동일 선택 기준 사용 |
| `avg_seconds` | 평균 소요시간 |
| `sample_count` | 유효 표본 수 |
| `baseline_source` | 값의 출처 |
| `stats_model_version` | 계산 방식·표본 구성·통계값을 고정한 통계 스냅샷 버전 |
| `updated_at` | |

**PK는 `(route_version_id, from_route_stop_id, to_route_stop_id, from_event_type, to_event_type, time_band_id, stats_model_version)`**이다.

`stats_model_version`은 08의 `path_model_version`과 **다른 축이다.** 경로 구성이 바뀌는 것과 통계 스냅샷이 바뀌는 것은 별개이므로 한 이름으로 세지 않는다. 예측이 어느 통계 버전을 쓸지는 08의 활성 `prediction_models` 행이 고정하며, 이 문서는 그 선택에 관여하지 않는다.

### 왜 이벤트 종류가 키에 들어가나

도착 간 · 출발 간 · 통과 간 통계는 **서로 다른 값**이다. 정차 시간이 어디에 포함되는지가 다르기 때문이다.

```
A 도착 ──── A 정차 ──── A 출발 ──── 이동 ──── B 도착
   └─────────── 도착→도착 ───────────────────────┘
                        └──── 출발→도착 ─────────┘
```

섞으면 정차 시간을 두 번 세거나 빼먹는다. **혼합하지 않는다.**

### 왜 날짜별 ID가 키에 없나

`trip_stop_id`는 날짜별이다. 여러 날 표본을 모으려면 **`route_stop_id`로 묶어야** 한다. 날짜별 ID로 묶으면 매일 표본이 1개인 통계가 생긴다.

`trip_stop_id`는 근거 표본 목록에만 둔다.

## 2. 표본 조건

`02` 4장의 규칙을 따른다. 아래를 **모두** 만족하는 이벤트 쌍을 **완결 구간**이라 하며, 완결 구간만 표본이 된다. 이 용어는 4장과 `07` 1장에서도 같은 뜻으로 쓴다.

| 조건 | 이유 |
|---|---|
| `time_confidence = observed` | 보간·추론은 실측이 아니다 |
| `validation_status = valid` | 취소·검토 대기 제외 |
| **같은 `trip_vehicle_id`, 같은 생산자 세션과 차량 배정 구간** | 다른 차량·인계·교체 전후를 연속 표본으로 합치지 않는다 |
| 두 이벤트 사이에 취소·누락 없음 | 중간이 비면 구간이 아니다 |
| 두 이벤트가 연속 방문 또는 동일 방문 arrived→departed | 같은 방문의 정차 통계는 양쪽 실측이 있을 때만 허용. 건너뛴 구간은 별도 |
| 소속 세션의 `ended_at IS NOT NULL` | 열린 세션은 회차 완료 여부와 무관하게 집계하지 않는다 |

### `interpolated`를 제외하는 이유

보간 시각은 두 GPS 좌표 사이의 추정이다. 오차가 전송 간격에 비례하므로 **학습에 넣으면 통계가 간격 설정에 오염된다.** 예측에는 쓰되 학습에서는 뺀다.

### 2대 운행

같은 회차의 두 차량은 별개 관측 대상이다. 1호차의 A 통과와 2호차의 B 통과를 한 구간 표본으로 만들지 않는다. `trip_vehicle_id`가 같아야 한다.

## 3. `baseline_source`

운행 기록이 없는 초기에는 다른 출처의 값을 쓴다. **어디서 왔는지 기록한다.**

| 값 | 의미 | `sample_count` |
|---|---|---|
| `manual_measurement` | 개발자가 직접 탑승해 측정 | 실제 측정 건수 |
| `school_timetable` | 학교 시간표의 주요 지점 시각에서 역산 | 0 |
| `estimate` | 임시 추정 | 0 |
| `operation_history` | 운행 기록 누적 | 누적 건수 |

`sample_count = 0`은 **측정값이 아니라는 표시**다. 실제 운행 기록이 쌓이면 `operation_history`로 대체된다.

### 시간표에서 얻을 수 있는 것과 없는 것

| 구간 | 시간표로 채울 수 있나 |
|---|---|
| 기점 → 종점 (평일 천안아산역 8:25→8:40) | ✅ `school_timetable` |
| 캠퍼스 → 외부역 (평일 천안역 7:40→8:15) | ✅ `school_timetable` |
| 중간 경유지 (탕정역, 시티프라디움 등) | ❌ 시간표에 시각이 없음 |
| 온양 노선 중간 (주은아파트, 아산터미널) | ✅ 시각이 공시됨 |

**온양온천역 노선을 제외하면 중간 경유지 구간은 직접 측정 없이 확보할 수 없다.** 측정 전에는 그 구간을 지나는 예측이 `missing_baseline`이다.

### 균등 분배 금지

전체 소요시간을 구간 수로 나눠 채우고 싶은 유혹이 있다. **공개 예측용으로 균등 분배하지 않는다.** `baseline_source = estimate`는 별도 실험 자료에만 허용하고 공개 travel_times 선택 대상에서 제외한다. sample_count=0 표시만으로 공개 사용이 허용되는 것은 아니다.

이 제외를 실제로 강제하는 곳은 **08 4장의 구간값 선택 단계**다. 여기서 행을 지우거나 숨기지 않고 그대로 보존하되, 공개 예측이 고르지 않는다. `school_timetable`은 공시 시각에서 역산한 값이므로 선택 대상에 포함한다.

## 4. 재계산

`recompute_travel_times(affected_segments)` — CronJob과 이벤트 트리거 양쪽에서 돈다.

### 정기 실행

수집이 종료된 세션 중 아직 통계에 반영되지 않은 완결 구간 기록을 처리한다.

- **동일 기록이 중복 집계되지 않게 한다.** 반영 여부를 표본 단위로 추적한다.
- 2장의 완결 구간 중 아직 반영되지 않은 것만 대상으로 한다. 회차가 계속 운행 중이어도 수집이 종료된 세션의 구간은 사용할 수 있다.

### 정정 후 재계산

집계 이후 입력 취소나 정정이 발생하면 **영향받은 구간의 통계를 유효 원본 기록에서 다시 계산한다.** 차분으로 빼지 않는다 — 부동소수 누적 오차와 순서 문제가 생긴다.

```
취소 발생
  → 그 이벤트가 속한 구간 식별
  → 해당 (route_version, from, to, event_type 쌍, band) 통계를
    유효 표본 전체로 재계산
```

### 모델 버전

계산 방식 변경뿐 아니라 표본 추가·취소·정정, 기준값 출처 변경으로 표본 구성이나 통계값이 달라져도 새 `stats_model_version`을 발급한다. 평균이 같더라도 표본 구성이 달라지면 새 버전이다. 동일 입력의 재시도는 기존 결과를 재사용한다. 확정된 버전의 행은 덮어쓰지 않는다. **버전을 올리는 것과 예측이 그 버전을 쓰기 시작하는 것은 별개다.** 새 통계 버전은 08이 새 `prediction_models` 행으로 검사·활성화할 때 비로소 공개 예측에 반영된다. 과거 예측 이력에는 `path_model_version`과 `stats_model_version`이 함께 남는다.

## 5. 정확도 평가

`eta_predictions`와 실제 관측을 사후 비교한다 (`08` 7장).

### 지표

| 지표 | 정의 |
|---|---|
| 절대 오차 | \|예상 시각 − 실제 시각\| |
| ±2분 이내 비율 | 목표는 초기 측정 후 확정 |
| 예측 제공률 | 전체 조회 중 ETA를 제공한 비율 |

**예측 제공률을 함께 본다.** 어려운 경우를 전부 `unavailable`로 처리하면 정확도는 올라가고 쓸모는 떨어진다.

### 나눠서 평가한다

- 노선별
- 구간별
- **시간대별** — `peak_morning` / `peak_evening` / `offpeak`
- **예측 선행 시간별** — 30분 전 예측과 3분 전 예측은 난이도가 다르다

통합 평균만 보면 피크의 큰 오차가 평시에 묻힌다.

### 학습과 평가를 분리한다

**통계 학습에 쓴 운행과 정확도 평가에 쓴 운행을 나눈다.** 같은 데이터로 학습하고 평가하면 오차가 과소평가된다.

`peak_morning`·`peak_evening`·`offpeak` **세 밴드 각각 최소 5회**를 초기 목표로 잡되, 이는 통계를 만들기 위한 최소치이며 **정확도 달성을 보장하지 않는다.**

### 근거 취소된 예측

실측이 취소되면 그 예측 이력을 삭제하지 않고 **평가에서 별도 분류한다.** 학생에게 실제로 보여준 값이었으므로 이력에서 지우면 안 된다.

### 도착 정확도라고 말하지 않는다

도착 시각을 수집하지 않았다면 통과 시각 오차로 평가하고, **통과 기준으로 평가했다는 사실을 명시한다** (`00` 5장).

## 6. 초기 측정 계획

측정 도구는 입력자 앱이다 (`06`). 스톱워치 대신 그것으로 재면 데이터가 바로 DB에 들어간다.

| 순서 | 할 일 |
|---|---|
| 1 | 버튼 기준 지점 확정 — 재현 가능한 기준 |
| 2 | MVP 노선을 2~3회 탑승해 전 구간 측정 |
| 3 | `baseline_source = manual_measurement`로 등록 |
| 4 | 시간대별로 최소 5회씩 추가 측정 |
| 5 | 평가용 운행을 별도로 확보 |

**측정은 실제 등교일에만 가능하다.** 달력 시간이 걸리므로 코딩과 병행한다 (`00` 7장).

## 9. 요일 구분과 예측 연결

표본은 05의 `effective_day_type`(weekday/saturday/sunday_holiday)으로 나누고 해당 그룹의 time_band_id에 적립한다. 같은 route_version이라도 평일과 휴일을 자동으로 합치지 않는다. 10/05는 sunday_holiday다. 표본이 적다는 이유로 다른 그룹을 묵시적으로 대체하지 않는다.

08의 resolve_time_band(route_id, effective_day_type, entry_at)과 동일한 분류를 사용한다. 표본은 시작 사건의 발생 시각으로 시간대를 정한다. 08은 활성 모델 행의 `path_model_version`과 `stats_model_version`을 함께 검증한 뒤 적용한다.

GPS 세션의 집계 대상 판정도 같은 규칙을 따른다. 4장의 "종료된 세션"에는 07 1장의 종료 사유로 닫힌 GPS 세션이 포함되며, 생산자 종류로 집계 여부를 가르지 않는다. 다만 표본 조건의 `time_confidence = observed`가 그대로 적용되므로 보간 이벤트는 여전히 제외된다.

시간표에서 구간 기준값을 만들 때 시작·종료 시각의 사건 종류가 확인되어야 한다. unspecified 시각을 도착 또는 출발로 가정해 통계 키를 만들지 않는다. 표본에는 시작·종료 event_id, 배정 구간, 시간대와 모델 버전을 추적 가능하게 남긴다.

### 통계 스냅샷 확정 절차

새 버전은 변경 구간의 재계산 결과와 변경 없는 구간의 복사본을 함께 담는 완전한 스냅샷이다. 공개 대상 노선·경로·시간대 전체를 포함하며 이전 버전의 행을 조회 시 섞어 보충하지 않는다. 표본이 모두 취소된 구간은 유효한 별도 기준값이 없으면 새 버전에서 제외한다. 이전 평균을 복사해 되살리지 않는다.

동일 입력 집합으로 일관되게 생성하고 동시 재계산은 직렬화한다. 생성 중 추가 정정은 다음 재계산 대상으로 남긴다. 불완전한 버전은 활성화 대상에 올리지 않는다. 표본 반영 추적은 해당 스냅샷 확정과 함께 기록하여 재시도 중 누락·중복을 막는다. 08의 검증 후 활성화 전에는 기존 활성 스냅샷 중 무효화되지 않은 행만 사용한다. 승격 게이트와 실행 시점은 08 4장이 소유하며 이 문서는 스냅샷을 만들 뿐 활성화를 판단하지 않는다. 롤백을 위해 직전 활성 스냅샷은 반드시 보존하고, 그보다 오래된 버전의 정리 기준은 미확정이다 (`00` NFR-12). 과거 예측을 재현할 수 있도록 이전 버전과 버전별 근거 표본을 보존한다.

| ID | 사례 | 기대 결과 |
|---|---|---|
| FR-TS-15 | 계산 방식은 같고 표본만 추가·취소 | 새 통계 버전 생성, 이전 평균·표본 목록 불변 |
| FR-TS-16 | 일부 구간만 통계 변경 | 변경 없는 구간도 새 스냅샷에 포함, 이전 버전 혼합 조회 없음 |

## 10. 표본 취소·복구와 기존 스냅샷의 사용 차단

travel_time_invalidations(stats_model_version, route_version_id, from_route_stop_id, to_route_stop_id, from_event_type, to_event_type, time_band_id, cause_event_id, reason, blocked_at)를 둔다. PK는 통계 행 전체 키와 cause_event_id의 조합이다. reason은 observation_cancelled / observation_rejected다. 무효화 기록은 지우지 않는다. 원래 travel_times의 값과 근거 표본은 과거 재현을 위해 그대로 남긴다.

취소·기각 시 버전별 근거 표본에서 해당 이벤트를 사용한 모든 통계 행을 찾아 멱등 차단한다. 등록을 트리거하는 곳은 02 9장의 입력자 취소와 13 13장의 관리자 기각이며, 두 경우 모두 취소 결정과 같은 트랜잭션이다. 표본 추적 목록은 스냅샷 확정과 함께 보존해야 한다. 단순 신규 표본 추가는 기존 통계의 무효화 사유가 아니다. 08은 차단 등록을 즉시 선택 조건에 적용하고 영향 상태를 갱신한다. 재계산·승격 보류와 무효 통계의 공개 사용 중단은 별개다.

오취소 복구는 기존 차단을 해제하지 않는다. 복구 후 유효한 표본 집합으로 새 스냅샷을 만들고 검증·활성화한다. 복구 사실만으로 과거 통계나 과거 예측을 다시 현재 값으로 공개하지 않는다.

|---|---|---|
| FR-TS-19 | 여러 스냅샷에서 사용한 관측 취소 | 참조하는 모든 행의 차단 기록 생성 |
| FR-TS-20 | 취소 요청 재전송 | 무효화 중복 없음 |
| FR-TS-21 | 취소 관측 복구 | 과거 차단 유지, 새 스냅샷에서만 재반영 |
