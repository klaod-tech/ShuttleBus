# 변경 기록

큰 변화만 적는다 — 설계 문서(md) 내용, 실제 기능 처리, 데이터 활용이 바뀐 것. 같은 항목을 다시 바꾸면 이전 기록을 지우고 최신으로 대체한다.

**최근 작업 3회분만 이 파일에 둔다** (날짜 간격이 아니라 작업 횟수. 2026-09-22 확정). 그보다 오래된 기록은 핵심 한 줄만 남기고 [보관 기록](CHANGELOG-ARCHIVE.md)으로 옮긴다.

## 2026-09-29

작업 관리판을 도입했다 (브랜치 `proto_dashboard`). 할 일의 **상태**가 ROADMAP 남은 작업·must_do·IMPROVEMENTS·README 진행 상황에 따로 적혀 있던 것을 관리판 카드 한 곳으로 옮겼다 — CLAUDE.md 1장 "규칙은 소유 문서 하나에만". 결정·순서·검증 결과는 [관리판 계획](PLAN-project-board.md).

| 무엇 | 어떻게 |
|---|---|
| 관리판 | `scripts/board/` — 표준 라이브러리만 쓰는 로컬 서버(`127.0.0.1:8774`). P0~P8 진행도, 할 일·진행·검수·완료 칸반, md 문서 서가. 루트 `관리판.cmd`로 연다 |
| 카드 | 기존 md 항목을 `SB-0001`~`SB-0098`로 등록 (완료 37 · 할 일 53 · 결정 필요 7 · 진행 1). 원래 ID는 카드 `ref`에 남겼다. 완료 카드의 근거는 md 기록을 옮긴 것이며 이관 때 재검증하지 않았다 |
| md 상태 문구 | 표 12개에 `카드` 열을 넣고 `**완료 (날짜)**`·취소선·`대기`·`미확보`를 카드 번호로 바꿨다. 행·ID·설명은 그대로다 — 코드 주석 19곳이 그 ID를 가리킨다. REVIEW·CHANGELOG 같은 기록은 고치지 않았다 |

## 2026-09-28

GPS Logger 시험 파일 후기(2026-09-23)를 코드로 확인하고, 실제 탑승 전에 고쳐야 할 것을 고쳤다.

| 무엇 | 어떻게 |
|---|---|
| **수신 공백을 직선으로 잇던 것** | 공백(`survey_max_gap_seconds` 30초 초과)에서 트랙을 **끊고 가장 긴 연속 조각만** 경로로 쓴다. 공백을 직선으로 잇지 않는다. 관측한 구간은 살리고 버린 점 수·가장 긴 공백을 알려준다. 규칙은 [PLAN-route-data](PLAN-route-data.md) '수신 공백이 났을 때' (`10` 5장) |
| **정차 판정** | 트랙 전체의 저속 점을 평균하던 것 → 시각·순번으로 **이어진 구간**만 정차로 본다. 10초 미만은 신호대기로 보고 제외 |
| **왕복 재방문** | 주석 반경 안에 30m 넘게 떨어진 정차가 또 있으면 어느 방문인지 확정하지 않는다 |
| **주석 이름** | 이름이 이 노선의 다른 정거장을 가리키면 좌표가 가까워도 붙이지 않는다. 이름이 없거나 모르는 이름이면 좌표를 따른다 |
| GPX 1.0 확인 | 같은 형식(1.0·`speed` 직계·`accuracy` 없음·녹화보다 이른 주석)을 만들어 적재→경로 생성까지 실행 확인. 회귀 시험 추가 |
| 임시 좌표 적재 | `samples/stops-provisional.json` 7개를 개발 DB에 넣었다. 전부 `needs_interpretation`이며 현장 확인 전까지 화면에 '확인 필요'로 나온다 |

설정 3개 신설: `survey_max_gap_seconds`·`survey_min_dwell_seconds`·`survey_distinct_dwell_m` (`01` 7장).
지도 표시 크기: 허용오차 5m에서 굽은 3.15km(273점)가 32점으로 줄어 폴리라인 부담이 없다.

검증: 서버 시험 **217개 통과**(공백 거절·정차 구간·이름 불일치·GPX 1.0 회귀 시험 4개 추가).

## 2026-09-23

GPS Logger 사용 후기를 현재 코드와 대조해 [IMPROVEMENTS](IMPROVEMENTS.md)에 실제 셔틀 적재 전 개선 순서·완료 조건을 기록했다. GPX 1.0 직접 speed·1초 간격·정확도 필드 부재를 사용자 관찰로 구분하고, 후기의 이름 검증 주장과 실제 거리 기반 매칭의 차이, 연속 정차·반복 방문·트랙 공백 처리 한계를 명시했다. [노선 자료 계획](PLAN-route-data.md)의 구현 상태·데모 검증 차단 설명도 최신화했다. 09-18 본문은 보관 기록으로 옮겼다.

검증 상태: 문서 및 코드 정적 대조·문서 차이 확인. 원본 GPX 미제공으로 수치 재검증 안 함. pytest·실지도 시험 안 함. DB 적재·제품 코드·설계 계약·P6 단계 변경 없음.
