# 변경사항 사전 점검 — 2026-09-21

## 결론

카카오맵 자체는 `http://localhost:3000` 브라우저에서 지도 타일·축척·Kakao 링크까지 정상 표시됐다. 실제 공백은 **정거장 좌표와 경로 자료가 없는 것**, **로컬 API 실행 시 루트 환경 파일을 읽지 못하던 것**, **점검 시작 당시 DB·API·화면 서버가 실행되지 않았던 것**으로 나뉜다. 키가 들어 있다는 사실만으로 성공 판정하지 않고 실제 화면으로 확인했다.

검토 기준은 HEAD `63630e8`과 최근 서버·화면 변경, 현행 설계 문서다. 기존 미추적 `AGENTS.md`는 수정하지 않았다. 전체 구현의 무결성이나 배포 준비 완료를 뜻하는 검토는 아니다.

## 실제 데이터 상태

로컬 PostgreSQL `127.0.0.1:55432/shuttlebus`를 시작한 뒤 읽기 전용 집계로 확인했다. Docker DB와 외부 배포 DB는 조사하지 않았다.

검토 중 실제 좌표·GPX·관측·계정은 추가하거나 변경하지 않았다. 브라우저 연결 확인을 위해 API는 `REALTIME_WORKERS=false`로 실행했으며, 자동 회차 보충·정리 작업은 실행하지 않았다. 날짜별 정거장 조회가 운행 달력 파생 결과를 저장하는 기존 동작은 수행됐다. 실제 데이터 준비 순서는 [경로 자료 계획](PLAN-route-data.md)을 따른다.

## 수정한 문제

**로컬 환경 파일 누락.** README대로 `cd api` 후 실행하면 기존 `Settings(env_file=".env")`는 `api/.env`만 찾았다. 실제 CORS 설정은 루트 `.env`에 있어 `cors_origins=[]`가 됐다. 키 문제가 없어도 브라우저의 API 조회는 차단될 수 있었다.

`api/app/config.py`가 실행 폴더와 무관하게 루트 `.env`, `api/.env` 순서로 읽게 수정했다. API 파일이 루트 값을 재정의하며 프로세스 환경변수가 최우선이다. API 경로·응답·DB 구조·설계 계약은 바꾸지 않았다. 설정 우선순위와 실행 폴더 독립성을 검사하는 시험 2개를 추가했다.

수정 후 CORS 설정이 로드되는 것을 확인했고, 브라우저에서 천안아산역 노선과 정거장 4개가 표시됐다. 모두 실제 DB 좌표가 없으므로 목록에 '좌표 확인 필요'가 나타나고 지도 마커는 없다.

## 카카오맵 확인 범위

- `web/.env.local`에 JavaScript 키 설정 존재를 값 노출 없이 확인했다.
- `localhost:3000`에서 실제 지도와 정거장 목록 렌더링을 확인했다. 키 재발급이나 카카오 계정 변경은 필요하지 않았다.
- 다른 도메인·모바일 접속·Docker 빌드는 미검증이다. JavaScript 키와 SDK 도메인 등록 요건은 [카카오 공식 가이드](https://apis.map.kakao.com/web/guide/)를 참고했다.
- 좌표·실제 GPX가 없으므로 마커 위치 정확도와 실제 도로 경로 표시는 검증할 수 없다. [데모 자료의 한계](PLAN-route-data.md)를 실제 운행 자료로 대체하지 않는다.
