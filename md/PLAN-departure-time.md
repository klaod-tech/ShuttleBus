# 출발 시각 선택 — 계획 (승인 대기)

- 분야: 서버
- 작업: SB-0107

2026-09-30 사용자 결정: 미래 날짜를 고르면 첫차 2개만 보이던 빈틈을 **출발 시각 선택**으로 메운다 (SB-0103 논의에서 A안). 화면은 네이버 지도 대중교통 길찾기의 '지금 출발'을 참고하되 **출발 기준만** 둔다(도착 기준 없음). 이 계획은 **API 계약 변경**(`11` 11장·후보 검색)이라 CLAUDE.md 2장에 따라 승인 전에는 구현하지 않는다.

## 1. 지금은 어떻게 되나

| 선택 날짜 | 서버 기준 시각 | 결과 |
|---|---|---|
| 오늘 | 지금 | 지금 이후 가까운 2개 |
| 미래 | 그날 첫차 | 첫차부터 2개 — "내일 9시쯤"을 찾을 수 없다 |
| 과거 | — | `past_date`로 빈 결과. 화면은 과거 날짜를 고르지 못하게 한다 (`md_frontend/02`) |

정거장 조회 `GET /stops/{stop_id}/upcoming`과 후보 검색 `GET /scheduled-trips?origin_stop_id&destination_stop_id` 모두 `service_date`만 받는다 (`api/app/api/stop_upcoming.py`, `api/app/api/trips.py`).

## 2. 화면 — '지금 출발' 칩

네이버 지도는 길찾기 결과 위에 기본값 **'지금 출발'**을 두고, 누르면 원하는 출발 시각(또는 도착 시각)을 고른다. 같은 구조로 하되 도착 시각 선택은 두지 않는다 (4장 2).

- 지도 위 노선·날짜 자리에 칩 하나: **`지금 출발 ▾`**. 날짜 선택을 따로 두지 않고 이 칩에 합친다.
- 누르면 아래에서 시트가 올라온다: `지금` 버튼 / 날짜(오늘부터, 과거 없음) / 시각 휠(5분 단위) / `확인`.
- 고르면 칩이 `10/1(수) 09:00 출발`로 바뀐다. 다시 `지금`을 누르면 기본으로.
- 정거장 카드와 출발·도착 검색이 **같은 칩 값**을 쓴다. 화면마다 따로 고르지 않는다.
- 오늘의 지난 시각은 고를 수 없다. 칩이 '지금'이 아니면 카드 머리에 "10/1 09:00 이후"를 적어 지금 상황이 아님을 밝힌다.

## 3. 서버 — `depart_after` 조건 (승인 필요)

두 조회에 같은 선택 조건 하나를 더한다. 없으면 지금과 똑같이 동작한다(하위 호환).

| 항목 | 내용 |
|---|---|
| 요청 | `depart_after=HH:MM` (서울 시각, 선택). `service_date`와 합쳐 기준 시각이 된다 |
| 기준 시각 | 오늘이면 `max(지금, 기준 시각)` — 지난 시각을 주면 지금으로 본다(기기 시계 차이 대비, 오류 아님). 미래면 기준 시각 그대로 |
| 정상 목록 | 기준 시각 이후 가까운 2개. 정렬·중복 제거·방향 합치기는 `11` 11장 그대로 |
| 지금 상황 항목 | 기준 시각이 지금보다 뒤면 `attention`(도착 확인·통과 확인 중)을 싣지 않는다 — 그 시각의 상황이 아니므로 |
| 예측 | 기준 시각이 먼 미래면 실시간 예측이 없어 시간표 기준(`display_basis: timetable`)이 된다. 새 규칙이 아니라 지금 계산 결과다 |
| 응답 | `depart_after_applied`(서울 시각, nullable) 추가 — 서버가 실제로 쓴 기준. 화면 칩 문구와 대조용 |
| 오류 | 형식이 틀리면 기존 `VALIDATION_ERROR`(422). 새 코드는 없다 |
| 설정 | 없음. 5분 단위는 화면 규칙이다 |

자정을 넘는 운행이 없어(07:30~22:30) 기준 시각이 날짜를 넘어가는 경우는 다루지 않는다 (`md_frontend/02` '다른 날짜와 자정').

## 4. 정할 것

1. **이 계약으로 구현해도 되나** — `depart_after` 이름·의미, `depart_after_applied` 응답 필드, 두 조회에 함께 적용.
2. ~~도착 기준도 둘까~~ — **두지 않는다** (2026-09-30 사용자 결정). 출발 시각 기준만 쓴다. "9시까지 학교 도착"은 가는 동안의 교통 상황을 감안해야 하고 그만큼 예측 부담이 커진다. 출발 기준은 시간표·관측의 출발 시각만으로 답할 수 있다. 별도 카드도 만들지 않는다.

## 5. 승인 뒤 순서

1. `11` 11장·후보 검색 절에 조건과 응답 필드를 적는다 (소유 문서).
2. `find_stop_upcoming`·`find_boarding_candidates`에 기준 시각을 넘긴다. 시험: 오늘 지난 시각 → 지금, 미래 09:00 → 09:00 이후 2개, 기준이 미래면 `attention` 없음, 조건 없음 → 기존과 같음 (`test_fr_…`).
3. `web/lib/api.ts` 타입에 `depart_after_applied`.
4. `md_frontend/01`·`02`의 날짜 선택 문구를 '지금 출발' 칩으로 바꾼다.
