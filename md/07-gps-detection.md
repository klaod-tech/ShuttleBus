# 07 · GPS 자동 판별 — Phase 2

> 차량 단말이 보낸 좌표에서 정거장 통과를 판별해 관측을 만든다. **Phase 1에는 필요 없다.**
> 참조: [공통 규약](01-conventions.md) · [관측 계약](02-observation-contract.md)

세션 구조는 `06`, 관측 의미는 `02`를 참조한다. 수동 UI의 동작을 재정의하지 않는다. 둘 다 `02`의 형식을 만들 뿐이다. **예측(`08`)은 이 문서를 읽지 않는다** — `time_confidence`만 본다.

---

## 1. 단말 인증과 배정

| 항목 | 규칙 |
|---|---|
| 토큰 | 관리자·입력자 토큰과 **분리한다** |
| 배정 | 단말은 차량에 사전 배정된다 |
| 회차 매핑 | 첫 유효 좌표 수신 시 producer_type=gps 세션이 없으면 멱등 생성. 수동 세션을 재사용하지 않음 |
| 후보 없음 | 배정하지 않고 `idle`로 둔다. 정상 상태이며 오류가 아니다 |
| 후보 중복 | **임의 배정하지 않는다.** 매핑 오류로 보관 |
| 수집 시간 | 운행 시간으로 제한한다 |

발급·회수 절차는 Phase 2 착수 시 확정한다.

차량에 담당 노선이 고정 배정되어 있으면 `device_route_assignments`로 등록하고 회차 후보를 그 노선으로 먼저 좁힌다. 고정 배정이 확인되지 않으면 좁히지 않고 아래 경계 규칙만 적용한다. **운영 사실을 확인하기 전에 고정 배정을 가정하지 않는다.**

### 회차 경계 — 기점이자 종점인 정거장

단말이 운행 시간 내내 켜져 있으면 좌표가 어느 회차에 속하는지를 서버가 정해야 한다. 아산캠퍼스는 여러 노선의 기점이자 종점이고 회차 간격이 짧으므로, 캠퍼스에 정차 중인 좌표만으로는 직전 회차의 종점 도착인지 다음 회차의 기점 대기인지 구분할 수 없다.

| 사건 | 판정 |
|---|---|
| 기점·종점 반경 **진입 후 정차** | 직전 배정 회차의 세션이 **열려 있는 동안에만** 그 회차의 종점 방문 판정 대상. 4장의 사건 종류 규칙을 그대로 적용한다 |
| 정차 지속 | **`idle`** — 어느 회차에도 배정하지 않는다. 직전 배정 회차의 세션이 닫힌 뒤의 정차가 여기 해당한다 |
| 반경 **이탈** | 이탈 시각이 어느 회차의 기점 공시 출발 시각 ±`trip_binding_window_seconds` 안이면 그 회차에 배정 |
| 이탈했으나 창 밖 | `idle` 유지. 차고지 이동·휴식으로 보고 회차를 만들지 않는다 |

`idle` 구간의 좌표는 원시 기록으로 보존하되 관측을 만들지 않는다. **배정 거부는 오류가 아니라 정상 상태다.** 캠퍼스 정차 중에는 직전 세션이 닫힌 idle 구간이며 다음 회차는 공시 정시 출발 전제를 쓰므로 예측에 필요한 근거가 없다. 매핑 오류 목록(`13` 8장)에는 창 안인데도 후보가 여럿이라 배정하지 못한 경우만 올린다.

### 세션 종료

GPS 세션에도 종료가 필요하다. 통계(`09` 4장)는 **종료된 세션의 완결 구간만** 집계하므로, 종료 규칙이 없으면 표본이 영원히 쌓이지 않는다.

| `end_reason` | 조건 | `ended_at` |
|---|---|---|
| `reassigned` | 같은 단말의 좌표가 다른 `trip_vehicle_id`에 유효 배정됨 | 새 배정 첫 좌표의 `measured_at` |
| `terminal_departed` | 현재 회차의 종점 차례와 검증된 연속 좌표의 진입 후 이탈이 모두 확인됨 | 이탈 좌표의 `measured_at` |
| `signal_lost` | 마지막 좌표 이후 `gps_session_idle_seconds` 경과 **그리고** 그 회차의 종점 예정 시각도 지남 | 마지막 좌표의 `measured_at` |
| `service_day_closed` | 운행일 마감 + 여유. CronJob 일괄 | 운행 마감 시각 |

**평가 순서는 위에서 아래다.** 한 좌표가 여러 사유를 동시에 만족할 수 있으므로 먼저 걸리는 것을 `end_reason`으로 기록한다. 특히 캠퍼스 이탈 좌표는 `terminal_departed`와 `reassigned`를 함께 만족하는데, 다음 회차가 배정되면 `reassigned`가 이긴다.

**경계 좌표는 새 세션에 속한다.** 이전 세션은 그 좌표의 `measured_at`을 `ended_at`으로 인용할 뿐 자기 표본에 넣지 않는다. 한 좌표가 두 세션의 수집 기간에 걸치면 `02` 6장 검사가 양쪽에서 통과해 중복 표본이 생긴다.

`terminal_departed`가 종점 `arrived`를 요구하지 않는 이유는 `dwell_min_seconds`가 미정인 동안 `arrived`가 아예 생성되지 않기 때문이다(6장). 그 조건을 걸면 하루 마지막 회차 세션이 `service_day_closed`까지 열려 있어 `09` 집계에서 빠진다. **종점 차례와 검증된 진입·이탈을 함께 확인한다.** 기점과 종점의 stop_id가 같아도 trip_stop_id와 방문 순서로 구분한다. 현재 회차의 기점 이후 진행 근거가 없거나 종점 차례가 모호하면 닫지 않는다. terminal_boundary_min_points개 이상의 유효 연속 좌표로 안쪽 진입과 바깥쪽 이탈을 각각 확인하며 시계·정확도·이동 연속성 검사를 먼저 적용한다. 반경 안팎으로 튀는 한 점은 종료 근거가 아니다. 설정 또는 검증 기준이 미정이면 terminal_departed를 적용하지 않고 다른 종료 사유를 기다린다.

상시 설치 단말은 회차에서 회차로 넘어가므로 실제로는 `reassigned`가 대부분을 닫는다. 나머지 셋은 안전망이다.

`ended_at`은 판정을 수행한 시각이 아니라 **근거 좌표의 `measured_at`**이다. 판정 시각을 쓰면 `02` 6장의 수집 기간 검사가 넓어져 무관한 지연 좌표까지 통과한다.

종료가 하지 않는 것:

- `operation_status`를 바꾸지 않는다. 수집 종료와 운행 완료는 다르다 (`13` 1장).
- `observed_completed_at`을 만들지 않는다.
- 관측 없는 방문을 확정하지 않는다. `unknown` 또는 `upcoming`을 유지한다.
- `skipped`를 자동 생성하지 않는다. 자동 누락은 후속 유효 관측이 있을 때만이다 (`02` 7장).

`end_reason`은 `06` 1장의 세션 열에 저장한다. 수동 세션은 null이다.

종료 후 같은 차량 슬롯에 좌표가 다시 오면 새 GPS 세션을 멱등 생성한다. 다만 `09` 2장이 같은 생산자 세션을 표본 조건으로 두므로 **세션이 쪼개지면 경계 구간의 표본이 버려진다.** `gps_session_idle_seconds`는 좌표 수신 공백 실측으로 조정한다. 좌표가 계속 들어오는 정상 주행은 방문 사이의 소요시간만으로 세션을 끊지 않는다.

## 2. 원시 좌표 저장

| 테이블 `device_positions` | 설명 |
|---|---|
| `position_id` | PK |
| `shuttle_id` | 배정된 차량 |
| `client_position_id` | 단말 측 ID. 멱등 처리 |

`POST /api/v1/device/positions` — `client_position_id`, `measured_at`, `latitude`, `longitude`, `accuracy_m`

## 3. 왜 점 판정으로는 안 되는가

좌표 한 점이 정거장 반경 안에 들어왔는지만 보면 **두 가지가 겹쳐 미검출이 난다.**

### 샘플 간격

전송 간격 5초, 반경 50m(지름 100m) 기준.

| 속도 | 5초 이동 거리 | 반경 통과 구간에 샘플이 걸리나 |
|---|---|---|
| 40 km/h | 56 m | 중심 통과의 이상적 조건에서는 포착 가능. 횡방향 거리·오차에 따라 누락 가능 |
| 60 km/h | 83 m | 중심 통과의 이상적 조건에서는 포착 가능. 비중심 경로는 누락 가능 |
| **80 km/h** | **111 m** | **놓칠 수 있음** |

오차 없이 중심을 지나는 직선·일정 속도라는 이상적 조건에서 `2 × radius ≥ v_max × interval`을 적용하면 반경 50m·5초의 한계는 20m/s = **72km/h**다. 일반 경로의 검출 보장이 아니다. 중심에서 d만큼 벗어나면 원 안 경로 길이는 `2 × sqrt(radius² - d²)`로 짧아지며 d≥radius이면 점 포착을 보장할 수 없다.

### 횡방향 오차

이쪽이 더 크다. 정류장 표지 좌표와 실제 주행 차선 사이가 **20~40m** 벌어지는 경우가 흔하다. 중앙차로나 반대편 정류장이면 더 멀다. 여기에 GPS 오차 10~20m가 한쪽으로 치우치면 **정통으로 지나가도 반경 밖**이다.

반경을 키우면 검출은 늘지만 인접 정거장·반대 방향 차량과 섞인다.

### 미검출이 예측을 고정시킨다

미검출이 나면 그 방문에 관측이 안 생긴다. 후속 방문이 잡히면 `passed_inferred`로 추론할 수 있지만 **`occurred_at`이 null이라 ETA 갱신에 쓸 수 없다** (`02` 4장). 연속으로 놓치면 예측이 기점 시간표 기준에 고정된 채 회복되지 않는다.

## 4. 판별 파이프라인

```
좌표 수신
  └ device_positions 저장 (도착 순서 그대로)
      └ 지연 창 대기 (detection_delay_seconds, 초기 15초)
          └ measured_at 순 재정렬          ← 1단계
              └ 경로 이탈 게이트            ← 아래를 막는 관문
                  └ 선분 판정              ← 2단계
                      └ 시각 보간          ← 3단계
                          └ 이벤트 생성    ← 4단계
                              └ 02 계약의 검증 통과 후 저장
```

### 1단계 — `measured_at` 순 재정렬

LTE가 끊겼다 붙으면 좌표가 버퍼에 쌓였다가 한꺼번에 온다. **`received_at` 순으로 처리하면 판정이 꼬인다.**

```
실제 이동:  정거장3 (08:31) → 정거장4 (08:35)
전송 도착:  정거장4 좌표 먼저 → 정거장3 좌표 나중
```

`received_at` 순이면 3을 4보다 뒤에 통과한 것으로 기록하거나 역행으로 거절한다.

**따라서 판별은 실시간 스트림 처리가 아니다.** 짧은 지연 창을 두고 그 창 안의 좌표를 `measured_at` 순으로 정렬해 처리한다. 창을 넘겨 도착한 좌표는 지연 보충 경로를 탄다 (`02` 6장).

### 2단계 — 선분 판정

점이 아니라 **연속한 두 좌표를 잇는 선분**과 정거장의 최단거리를 본다.

```
P1(t1) ──────────────── P2(t2)
              ╲ d
               ╲
                S (정거장)
```

```
v = P2 − P1
u = clamp( ((S − P1) · v) / |v|² , 0, 1 )
closest = P1 + u·v
d = |S − closest|

d ≤ geofence_radius_m  →  통과 후보
```

샘플이 정거장 정면에 없어도 잡히고, 간격이 벌어져도 선분이 반경을 관통하면 검출된다. **샘플 사이 누락을 줄일 수 있지만 긴 간격·급격한 경로 변화·좌표 오차에 대한 제한은 여전히 필요하다.**

### 3단계 — 시각 보간

최근접점의 매개변수 `u`로 통과 시각을 얻는다.

```
occurred_at = t1 + u × (t2 − t1)
time_confidence = interpolated
```

두 실측 좌표 사이의 보간이므로 **시각을 지어낸 것이 아니다.** 그렇다고 직접 관측도 아니다. `02` 4장의 규칙에 따라 **예측에는 쓰고 통계 학습에서는 뺀다.**

`u`가 0 또는 1에 가깝다는 이유만으로 observed로 바꾸지 않는다. 선분으로 구한 통과 시각은 interpolated를 유지한다. measured_at을 직접 쓸 때도 그 표본이 도착·출발·통과 중 어느 사건의 기준을 충족했는지 검증해야 한다.

### 4단계 — 이벤트 종류 판정

**반경 진입 한 번으로 `arrived`를 만들지 않는다.**

| 근거 | 판정 |
|---|---|
| 반경 안에서 속도가 0에 가깝고 `dwell_min_seconds` 이상 체류 | `arrived` |
| 체류 후 반경을 벗어나며 속도 회복 | `departed` |
| 반경을 통과했으나 체류 근거 없음 | `passed` |
| 근거 부족 | 판별 미확인 — 이벤트를 만들지 않음 |

공식 안내가 중간 승차지에서 손을 들어 의사를 표시하라고 요구한다. **모든 경유지의 정차가 보장되지 않으므로** 반경 통과를 도착으로 단정하지 않는다.

### 판정에서 함께 확인하는 것

- **다음 방문 순서** — 회차의 남은 방문 중 어느 것인지
- **진행 방향** — 반대 방향 차량이나 가까운 다른 도로를 배제
- **연속 좌표** — 한 점의 튐으로 판정하지 않음
- **좌표 흔들림** — 같은 방문에 대한 중복 이벤트 방지

아산캠퍼스는 **여러 노선의 기점이자 종점**이므로 노선 판별에 특히 주의한다. 휴일 천안역 패턴에서는 천안아산역이 한 회차에 두 번 등장하므로 `trip_stop_id` 단위로 판정한다.

### 경로 이탈 게이트

단계가 아니라 **관문이다.** 재정렬 뒤에 판정하고, 이탈 중이면 2~4단계를 수행하지 않는다.

**판정 보류 창으로 동작한다.** 이탈은 연속 점을 모아야 확정되므로 좌표마다 즉시 막으면 확정 직전의 점들로 이미 이벤트가 생성된다. 재정렬된 좌표를 버퍼에 보관하고 이탈 후보가 시작되면 해당 점 이후의 선분 처리를 보류한다. 거리 초과 점이 route_deviation_min_points개 이상 연속하면 그 후보 구간 전체를 이탈로 제외한다. 그 전에 경로 위로 돌아온 고립 이상점은 원본만 보존하고 이를 끝점으로 쓰거나 앞뒤를 이어 가짜 선분을 만들지 않는다. 복귀에는 route_rejoin_min_points개 이상의 연속 경로 위 점을 요구하며 복귀 구간 내부에서 새 연속열을 시작한다. 단말 종료·신호 두절로 판단하지 못한 버퍼는 원본과 미확인으로 남기고 강제 확정하지 않는다. 대기 시간은 `detection_delay_seconds`와 이 버퍼 중 **긴 쪽**을 따른다.

정거장 반경만 보면 **차량이 노선을 벗어난 상태를 알 수 없다.** 우회·오배정·다른 도로 주행 중에도 우연히 어떤 정거장 반경을 스치면 통과로 잡힐 수 있다.

**좌표 한 점**과 `route_path_points` 폴리라인의 최단거리로 판정한다. 4장 2단계의 점-선분 거리 계산식을 재사용하되 역할이 뒤바뀐다 — 4장 2단계는 좌표 선분과 정거장 점, 여기서는 좌표 점과 경로 선분이다.

```
d_route = min( 폴리라인의 각 선분까지의 최단거리 )

d_route ≤ max_route_deviation_m                     → 경로 위
거리 초과 점이 연속 route_deviation_min_points개 이상 → 이탈
이탈 후 연속 route_rejoin_min_points 점이 경로 위    → 정상 복귀
```

진입과 복귀가 모두 **연속 점 수**를 요구한다. 좌표 한 점의 튐으로 상태를 뒤집지 않기 위해서이며, 2장에서 한 점 판정을 쓰지 않는 것과 같은 이유다.

이탈로 확정된 점을 끝점으로 갖는 선분은 2단계 입력에서 제외한다. 경로 위 점과 이탈 점을 이은 선분은 실제 주행을 나타내지 않는다.

**새 공개 상태를 만들지 않는다.** 이탈은 03의 기존 계약으로 흘려보낸다.

| 이탈 중 | 처리 |
|---|---|
| 통과 이벤트 | **생성하지 않는다.** 이탈 구간의 좌표로 방문을 확정하지 않는다 |
| 마지막 유효 관측 | 유지한다. 뒤로 옮기지 않는다 |
| 공개 상태 | `information_status = unavailable`, 해당 방문은 `unavailable_reason = position_unverified` |
| 학생 화면 | 03 6장 6단계의 ‘위치 확인 중’ |
| 예측 | **제공하지 않는다.** `08` 6장의 `position_unverified` 규칙에 따라 `estimated_event_at = null`이다 |
| 복귀 | 이탈 구간 동안 지나친 방문을 자동 확정하지 않는다. 개선사항 1순위의 공백 복원과 같은 제약을 받는다 |

마지막 유효 관측 자체는 **폐기하지 않는다.** 복귀하면 그 근거로 예측을 재개하며, 그 사이 `observation_grace_seconds`를 넘겼으면 `stale_observation`으로 전이한다. 예측을 멈추는 것과 근거를 버리는 것은 다르다.

학생에게는 좌표가 오래된 것과 경로를 벗어난 것이 모두 ‘지금 이 차량 위치를 신뢰할 수 없다’로 같다. **내부 사유만 구분하고 화면 문구는 하나로 유지한다.**

이탈 판정은 route_stop_segments.verification_status=verified이고 구간 및 연결 경로 점의 path_source가 manual_trace가 아닌 구간에서만 수행한다. 현재 진행 순서·방향으로 가능한 구간을 먼저 좁힌다. 부분 경로의 끝 이후나 가능한 구간이 미검증·혼합·누락이면 판정 불가이며, 먼 검증 구간과의 거리로 이탈을 확정하지 않는다. 자료가 없거나 미검증인 구간에서는 자동 경로 기반 방문 확정·공백 복원을 수행하지 않는다. 독립적인 수동 관측과 검증된 직접 GPS 사건은 02의 검증을 거쳐 처리할 수 있다.

## 5. 수신 중단과 복구 확인 과제

좌표가 늦거나 끊기면 원시 마지막 측정·수신 시각을 보존하고 위치 상태를 locating으로 표시한다. 학생 문구는 ‘위치 확인 중’이다. 수신 재개 후 원시 좌표의 중복·순서·정확도를 검증한다.

좌표가 노선의 다음 구간에 있다는 이유만으로 지난 방문을 자동 확정하는 기능은 개선사항 1순위의 자료 등록을 기다린다. 학교 문의로는 공식화된 자료를 확보할 수 없음이 확인되어, 실제 주행 경로·우회·왕복 방향·단말 저장 및 재전송 가능 여부는 사용자가 업체 문의 또는 현장 확인으로 확보하는 것으로 방침을 확정했다. 3~4장의 선분·보간은 연구용 설계이며 검증된 경로와 기준을 갖추기 전 공백 복원에 자동 적용하지 않는다.

확인된 자료는 `route_path_points`·`route_stop_segments`에 들어간다 (`04` 1장). 공백 복원은 대상 구간이 verified이고 연결 경로가 검증된 경우에만 적용 후보가 된다. 행 존재만으로 켜지 않으며 복원 기준과 실제 자료 검증을 함께 요구한다. `path_source = manual_trace`인 구간은 도로 중심선 추정이므로 지도 표시에만 쓰고 이 판정에는 쓰지 않는다.

예상 시각 경과는 교통 지연일 수도 있으므로 detection_missed를 공개 방문 상태로 만들지 않는다. 원시 자료와 내부 점검 이력에만 남긴다. 관측 없는 방문은 unknown 또는 upcoming이며 화면은 03의 확인 중·시간표 안내를 사용한다. 상세 확인 목록은 [개선사항](IMPROVEMENTS.md)을 따른다.

## 6. 설정값

| 이름 | 판단하는 것 | 초기값 | 상태 |
|---|---|---|---|
| `gps_report_interval_seconds` | 단말 전송 주기 | 5 | 시험값 |
| `geofence_radius_m` | 정거장 반경 | 50 | 시험값. **정거장별로 다를 수 있음** |
| `detection_delay_seconds` | 재정렬 지연 창 | 15 | 시험값 |
| `dwell_min_seconds` | 정차로 볼 최소 체류 | — | **미정** |
| `detection_grace_seconds` | 내부 통과 미확인 점검 여유 | — | **미정** |
| `gps_stale_after_seconds` | 신호 만료 — 위치 배지를 locating으로 내림 | 90 | 시험값 |
| `gps_session_idle_seconds` | 좌표 두절로 세션을 닫을 시점 | 2700 | 시험값 |
| `terminal_boundary_min_points` | 종점 진입·이탈 각각의 연속 유효 좌표 수 | — | **미정** → terminal_departed 미적용 |
| `trip_binding_window_seconds` | 기점 이탈을 어느 회차에 붙일 허용 범위 | 900 | 시험값 |
| `max_route_deviation_m` | 폴리라인에서 이만큼 벗어나면 이탈 후보 | — | **미정** → 이탈 판정 미수행 |
| `route_deviation_min_points` | 이탈로 확정할 연속 점 수 | — | **미정** → 이탈 판정 미수행 |
| `route_rejoin_min_points` | 정상 복귀로 볼 연속 점 수 | — | **미정** → 이탈 판정 미수행 |
| `max_interpolation_gap_seconds` | 이 간격을 넘는 두 좌표는 보간하지 않음 | — | **미정** |
| `max_position_accuracy_m` | 이 오차를 넘는 좌표는 판정에 쓰지 않음 | — | **미정** |
| `max_plausible_speed_mps` | 물리적으로 불가능한 이동을 거름 | — | **미정** |
| `raw_position_retention_days` | 원시 좌표 보존 | — | **미정** |

`gps_stale_after_seconds`는 **좌표**의 나이를 재고 `observation_grace_seconds`(`08` 6장)는 **통과 기록**의 나이를 잰다. 정거장 사이를 정상 주행하는 동안 좌표는 계속 들어오지만 통과 기록은 구간 소요시간만큼 늙으므로 두 값의 자릿수가 다르다. **한쪽 값을 다른 쪽에 재사용하지 않는다.**

`gps_session_idle_seconds`의 2700초는 좌표 두절을 판단하는 시험값이다. 공시 구간 길이로 산정한 최종값이 아니다. 좌표가 계속 들어오면 구간 주행이 길어도 이 조건으로 세션이 종료되지 않는다. 신호 두절 지속시간과 종점 예정 시각 경과라는 1장의 두 조건을 함께 적용한다. 수신 공백·재전송 지연을 실측하여 최종값을 정하고, 세션 분할로 경계 표본이 제외되는 영향도 확인한다.

**5초·50m는 고정된 정답이 아니다.** 실제 노선, 단말 오차, 도로와 정류장 사이 거리에 맞춰 조정한다. `geofence_radius_m`은 정거장마다 다르게 둘 수 있도록 `stops`에 열을 둔다.

경로 이탈 값 셋은 실제 트랙에서 폴리라인까지의 거리 분포를 보고 정한다. 셋 중 하나라도 미정이면 **이탈 판정을 수행하지 않는다.** 판정을 하지 않는 것이 잘못된 임계값으로 정상 주행을 이탈로 막는 것보다 안전하다.

미정 값이 설정되기 전에는 보수적으로 동작한다 — `dwell_min_seconds`가 없으면 `arrived`를 만들지 않는다. 통과를 입증하는 좌표·방향·이탈 근거가 있을 때만 `passed`를 만들고 나머지는 미확인으로 둔다. 또한, `detection_grace_seconds`가 없으면 통과 미확인 점검을 시작하지 않는다.

## 7. 반경·간격 실측

지도만으로는 도로와 정류장 사이 거리를 정확히 알 수 없다. **한 노선을 실제로 타면서 좌표를 기록해 정한다.**

측정할 것

1. 각 정거장에서 실제 주행 차선까지의 횡방향 거리
2. 정거장 부근 실제 속도
3. 단말이 보고하는 `accuracy_m`의 실제 분포 — 조사 트랙에서는 얻지 못할 수 있다(아래)
4. 같은 구간을 여러 번 지날 때 좌표의 재현성

이 값들로 정거장별 `geofence_radius_m`을 정하고, 폴리라인까지의 거리 분포로 `max_route_deviation_m`을 정한다.

**`accuracy_m`은 조사 트랙에서 얻지 못할 수 있다.** 표준 GPX에는 그 필드가 없고 `sat`·`hdop`·`fix`만 있어, 기록 앱이 확장 요소로 넣은 경우에만 나온다. 없으면 `hdop`를 대리 지표로 쓰되 같은 값으로 취급하지 않는다. 조사 기기와 운행 단말은 서로 다른 기기이므로 **`max_position_accuracy_m`의 최종값은 Phase 2 실제 단말의 보고값으로 정한다.** 조사 트랙의 분포는 참고값이다.

## 8. 수동 기록과 비교 검증

Phase 2 초기에는 **수동 입력과 GPS를 동시에 돌린다.** 같은 방문을 두 경로가 기록하되 유효 이벤트는 하나이고, 다른 하나는 `needs_review`로 보관해 비교한다 (`02` 10장).

측정 지표

| 지표 | 정의 |
|---|---|
| 누락률 | 수동으로 기록된 방문 중 GPS가 못 잡은 비율 |
| 오검출률 | GPS가 만든 이벤트 중 수동 기록과 맞지 않는 비율 |
| 판별 시각 오차 | 같은 방문의 GPS `occurred_at` − 수동 `occurred_at` |
| 종류 오판율 | `arrived` / `passed`를 잘못 판정한 비율 |
| 보간 비율 | 전체 GPS 이벤트 중 `interpolated`의 비율 |

보간 비율은 누락률·오검출률·시각 오차와 함께 평가한다. 비율 하나만으로 반경을 키우지 않는다. 수동 기준 기록도 누락될 수 있으므로 원시 좌표와 비교 기록을 함께 검토한다.

지표가 안정된 뒤에 수동 입력을 선택 사항으로 내린다. 그전까지는 수동이 기준이다.

## 9. 하지 않는 것

- 반경 진입 한 번으로 통과·도착을 확정하지 않는다.
- 후보 회차가 없거나 여러 개일 때 임의 배정하지 않는다.
- 수동과 GPS가 같은 방문을 나타낼 때 중복 집계하지 않는다.
- 신호가 끊긴 동안의 위치를 추정해 채우지 않는다. 마지막 측정 시각을 보여준다.
- Phase 2에는 검증된 실제 좌표 갱신으로 차량 마커를 움직일 수 있다 (`10`). 관측하지 않은 중간 좌표를 생성해 가상 이동시키지 않는다.
- 원시 좌표를 통과 기록과 같은 보존 정책으로 묶지 않는다.

## 12. 선분 계산의 전처리와 거부 조건

WGS84 원시 좌표는 보존하되 선분 거리 계산은 지역 미터 좌표계로 변환한 P1·P2·S에 적용한다. 위도·경도 도 단위를 미터 반경과 직접 비교하지 않는다.

- 동일 생산자·차량 배정·회차의 연속 좌표만 연결한다. 배정 변경 경계를 잇지 않는다.
- t2<=t1이면 보간하지 않는다. 동일 측정 ID 재전송은 원시 위치 멱등 규칙으로 처리한다.
- |P2-P1|²=0이면 나눗셈을 하지 않는다. 체류 증거로만 보관하고 통과 선분을 만들지 않는다.
- `max_interpolation_gap_seconds`, `max_position_accuracy_m`, `max_plausible_speed_mps`를 적용한다(6장 설정값 표). 값이 미정이면 보간을 자동 확정하지 않고 원시 좌표를 보존한다.
- 통신 공백을 가로지르는 긴 직선이나 다른 도로를 잇는 좌표열은 통과 증거로 사용하지 않는다. 진행 방향·다음 방문·확인된 경로와 일치하는지 함께 검사한다. 경로 일치 판정은 4장의 경로 이탈 게이트를 따른다.
- 단일 선분이 여러 정거장을 지날 경우 방문 순서와 보간 시각 순서가 모두 일치해야 한다. 같은 좌표의 반복 방문을 한 번에 전부 확정하지 않는다.

`device_positions`에는 device_id·배정 이력 ID도 저장하고 `(device_id, client_position_id)`로 원시 위치 유일성을 보장한다. 발생 시각과 연결된 시계 검증 근거는 02를 따른다. GPS 비교 단계의 대표 관측 선택은 02의 manual_reference 정책을 따른다.
