## 수정해야 할 점

### P1 — CLI 데모 허용 옵션이 실제 DB에 검증 완료를 저장한다

위치: `api/app/survey.py` 463~464, 575~576행.

`--allow-demo`는 단순 계산 시험 옵션이 아니다. 이 옵션은 데모 차단을 해제하고 `verify_path`가 구간을 verified로 바꾼 뒤 CLI가 평소처럼 commit한다. 별도 시험 DB 제한이나 rollback이 없다. 시각이 다른 두 데모 기록을 사용하면 자기 기록 검사도 통과한다.

따라서 변경 기록의 "데모 자료가 verified가 되던 것을 막았다"는 설명은 기본 옵션에만 해당한다. 실제 자료 원칙을 보장하려면 CLI에서 우회 옵션을 제거하거나 데모 검증을 저장하지 않는 별도 시험 경로로 분리해야 한다. 시험 함수의 명시적 허용과 실제 DB에 저장하는 CLI를 구분해야 한다.

검증: 실제 DB 없이 메모리 세션 대역으로 서로 다른 시각의 데모 검증을 실행했다. `allow_demo=True`에서 `verified=1`, 구간 상태 verified가 되는 것을 재현했다. CLI commit 연결은 정적 확인했다.

### P1 — 시각 없는 GPX는 자기 검증 차단을 통과한다

위치: `api/app/survey.py` 437~439행.

GPX 적재와 경로 생성은 측정 시각이 없는 점도 허용한다. 그런데 경로 점 시각 집합이 비어 있으면 `_same_recording`은 False를 반환한다. 즉 동일 기록인지 확인할 수 없는 상황을 별도 기록인 것처럼 통과시킨다. 같은 좌표의 시각 없는 기록으로 검증하면 verified가 될 수 있다.

독립된 실제 탑승 기록임을 입증하지 못하면 검증 완료로 승격하지 않아야 한다. 당장은 출처 확인 불가 시 거부하고, 장기적으로 정제 경로와 원본 트랙의 명시적 연결을 검토한다. 출처 열 추가는 [작업 지침](../CLAUDE.md) 2절의 스키마 승인 대상이다. 비교용 트랙만 검사하는 현재 구조로는 기존 경로가 데모에서 만들어졌는지도 충분히 확인할 수 없다.

검증: 짧은 두 점 경로와 같은 좌표의 시각 없는 기록을 메모리 세션 대역으로 비교했다. `allow_demo=False`에서 `verified=1`을 재현했다. 실제 GPX를 DB에 적재하는 종단 시험은 이번에 수행하지 않았다.

### P2 — 설정 이관 뒤 새 판정 상수가 다시 생겼다

위치: `api/app/survey.py`의 `SAME_RECORDING_OVERLAP = 0.9`.

자기 기록 판정의 90%는 물리 상수가 아니라 판정 기준이다. `Settings`와 `01` 설정 인덱스에 등재하고 근거·한계를 기록해야 한다. 시각 겹침률 자체로 독립 기록을 완전히 보장할 수는 없으므로 위 출처 확인 보완을 대신하지 않는다.

### P2 — 화면의 이전 두 항목은 남아 있다

- `web/components/KakaoMap.tsx`: `MapStop.verified`를 마커 표시에 사용하지 않아 미확인 좌표를 등록해도 확인된 좌표와 구별되지 않는다.
- `web/app/page.tsx`: 취소된 경로 요청의 catch도 `setPaths([])`를 실행한다. 요청 취소를 무시하거나 요청 세대를 확인하도록 보완해야 한다.

두 항목은 코드 정적 확인이다. 좌표 없는 현재 화면으로 미검증 마커 구분을 검증했다고 보지 않는다. 화면 구현은 외부 담당 범위다.
