# 10 · 정거장 선택

> 학생이 지도나 목록에서 정거장을 고른다. 고른 뒤의 후보 조회는 `11`이 맡는다.
> 참조: [공통 규약](01-conventions.md) · [기준 데이터](04-reference-data.md)

선택 노선·날짜와 origin_stop_id(탈 곳), destination_stop_id(내릴 곳)를 11에 전달한다. 전체 노선 페이지·검색은 후순위다. 현재는 설정 또는 진입 경로에서 선택한 route_id로 시작한다.

---

## 1. 학생 이용 흐름

```
1. 노선과 운행 날짜 선택
2. 날짜 자료 상태·공지 조회
3. 지도 마커 또는 목록에서 출발·도착 정거장 선택 ← 이 문서
4. 출발 이후 목적지에 방문하는 회차·차량 후보 표시     ← 11
5. 후보 선택 → 상세 표시                       ← 11, 03
6. 실시간 갱신                                 ← 12
```

MVP 노선은 확정 전이며 **실제 탑승할 노선을 우선한다.**

## 2. 지도

카카오맵 JavaScript SDK를 우선 설계안으로 쓴다. 네이버지도는 대안이며 **두 SDK를 동시에 도입하지 않는다.**

시간표·셔틀 위치·ETA는 전부 자체 서버 데이터다. **외부 지도 API가 이 학교 셔틀의 실시간 위치나 ETA를 제공한다고 가정하지 않는다.** 학교 정거장은 자체 DB에 좌표를 등록하므로 장소 검색 API도 초기에는 필요 없다.

### 사용하는 SDK 기능

| API | 목적 |
|---|---|
| `kakao.maps.Map` | 지도 생성 |
| `kakao.maps.LatLng(latitude, longitude)` | WGS84 좌표 변환 |
| `kakao.maps.Marker` | 정거장·차량 마커 |
| `kakao.maps.event.addListener(marker, 'click', handler)` | 정거장 선택 |
| `kakao.maps.LatLngBounds`, `map.setBounds()` | 전체 정거장이 보이도록 범위 조정 |
| `map.panTo()` | 선택한 정거장으로 이동 |

### 로드 규칙

```
https://dapi.kakao.com/v2/maps/sdk.js?appkey={JAVASCRIPT_KEY}
```

- 브라우저에서 **한 번만** 로드하고 로드 완료 후 지도를 만든다.
- Next.js 서버 렌더링 단계에서 `window.kakao`에 접근하지 않는다.
- 화면 해제 시 지도 이벤트와 참조를 정리한다.
- JavaScript 키와 개발·배포 도메인을 콘솔에 등록한다.
- `NEXT_PUBLIC_KAKAO_MAP_JS_KEY`는 **브라우저에서 보이는 값**이다. 서버 비밀 키를 공개 변수에 넣지 않는다.
- 계정의 사용 설정·쿼터·과금은 실제 공개 전 확인한다.

### 지도가 실패해도 서비스는 동작한다

**지도 로딩 실패 시에도 목록·시간표·ETA를 유지한다.** 지도는 정거장 선택의 한 가지 방법일 뿐이다.

지도 열람과 정거장 선택에 **학생의 위치 권한이 필요하지 않다.** '내 위치'는 후속 선택 기능이다.

## 3. 마커와 목록

**같은 선택 함수를 쓴다.** 마커를 누르든 목록을 누르든 동일한 상태가 된다.

목록은 접근성 대안이자 지도 실패 시 대체 경로다. 화면이 좁을 때도 목록이 기본이 될 수 있다.

### 무엇을 표시하나

`GET /routes/{route_id}/stops`에 **`service_date`를 필수로 보낸다.** 천안역 노선은 평일과 휴일의 방문 목록이 다르다 (`04` 1장). 날짜 없이 "오늘"을 가정하면 주말에 평일 정거장을 보여준다.

| 표시 | 출처 |
|---|---|
| 정거장 이름 | `stop_name` |
| 방문 순번 | `stop_sequence` |
| 방향 | 패턴의 `direction` |
| 승하차 가능 여부 | `boarding_policy`, `alighting_policy` |

## 4. 같은 좌표, 다른 방문

**아산캠퍼스는 출발 방문과 종점 방문이 같은 좌표다.** 지도에서는 마커 하나로 보이지만 `trip_stop_id`가 다르다.

| 규칙 | 내용 |
|---|---|
| 마커 | 물리적 정거장 하나에 마커 하나 |
| 선택 결과 | 출발·도착 stop_id 쌍 → 11이 같은 회차의 순서가 맞는 승하차 방문 쌍으로 펼침 |
| 종점 방문 | **탑승 출발 후보로 추천하지 않는다.** 하차만 가능하다 |

휴일 천안역 패턴에서는 **천안아산역이 한 회차에 두 번** 등장한다. 마커는 하나이며 목적지와 방문 순서에 맞으면 서로 다른 승차 방문 후보가 생긴다.

반복 방문과 반대 방향 정거장을 혼동하지 않는다.

## 5. 버스 위치 표시

### Phase 1 — 가상 이동 없음

**정거장 사이에서 움직이는 버스 아이콘을 만들지 않는다.** 수동 입력은 정거장 통과 시점만 알 뿐 그 사이 위치를 모른다.

마지막 확인 정거장에 **'마지막 확인' 표시**를 붙이는 것이 전부다.

### Phase 2 — 실제 좌표만

유효한 GPS 좌표를 별도 차량 마커로 표시한다.

- 측정 시각을 함께 보여준다.
- 오래된 좌표는 흐리게 구분한다.
- 신호가 끊긴 동안의 위치를 추정해 채우지 않는다.

### 정거장 연결선

정거장을 직선으로 이으면 **'정거장 연결선'으로 표시한다.** 실제 주행 경로로 오인시키지 않는다.

실제 경로를 그리려면 별도로 확인한 노선 경로 좌표가 필요하다. 그 자료는 `route_path_points`에 있으며(`04` 1장), 해당 경로 버전에 행이 있으면 연결선 대신 실제 경로를 그린다. `path_source`가 `manual_trace`이면 추정 경로임을 함께 표시한다. 천안아산역 노선의 귀교 경로는 입력 자료가 역→학교로만 표현하므로 **탕정역·시티프라디움을 역순으로 자동 추가하지 않는다** (`04` 11장).

## 6. 실제 승차 위치

**MVP에 포함한다.** 후속으로 미루지 않는다.

### 공대와 학생회관

학기 중 평일 **13:30~15:30 / 19:30 이후**에 학생회관 승강장이 승차 지점으로 안내된다. 공대 승강장을 대체하는지 추가되는지는 확인 전이다(아래 미확정 행). 해당 회차 목록은 `04` 7장에 있다.

| 규칙 | 내용 |
|---|---|
| 비교 시각 | 해당 회차의 **캠퍼스 출발 공시 시각**(`scheduled_stop_times`). 학생이 조회하는 현재 시각이 아니다 |
| 경계 | **양 끝 포함** `[13:30, 15:30]`과 `[19:30, 24:00)`. `time_bands`의 반열린과 다르다 (`01` 2장) |
| 캠퍼스 출발이 없는 회차 | 중간노선 전용은 비교할 시각이 없으므로 **해당 없음**으로 둔다 |
| 금요일 | 실제 존재하는 회차와의 교집합만 적용 |
| 좌표 | **공대와 학생회관을 같은 좌표 하나로 합치지 않는다** |
| 미확정 | 추가 승차지인지 공대 대체인지 확인 전에는 단일 승차지로 확정하지 않고 확인 필요를 표시 |
| 휴일 | 휴일 시간표에는 안내가 없다. 적용 여부 확인 필요 |

### 정거장 상세에 제공하는 공식 안내

| 안내 | 내용 |
|---|---|
| 승차 의사 표시 | 중간 승차지에서는 차량 확인 후 **손을 들어** 승차 의사를 표시한다 |
| 하차 | 하차 전 차량의 **하차벨**을 누른다 |
| 결제 | 선·후불 교통카드 사용 가능(수협·시티 제외), **현금 불가**. 금액은 공식 자료에 없으므로 추정하지 않는다 |

**앱의 정거장 선택은 기사에게 보내는 승차 요청이 아니다.** 앱 버튼은 실제 하차벨과 연결되지 않는다. 승차 요청 전송 기능은 범위에 없다.

이 안내는 **`boarding_policy = unknown`인 경유지가 왜 '탑승 가능'으로 표시되면 안 되는지**의 근거이기도 하다. 정거장 경유가 매번 정차를 뜻하지 않는다.

### 좌표 미확정 처리

정거장 좌표를 실측하기 전에는 지도 마커 표시를 보류하고 목록으로만 제공한다. `선문대`와 `아산캠퍼스`가 같은 지점인지, `펜타포트`가 어디인지 확인되지 않았다 (`04` 11장).

공식 문서가 '아산역·천안아산역'을 함께 표기하므로 **지도 핀은 실제 셔틀 승차 위치를 확인한 뒤 지정한다.**

## 7. 프론트 상태

| 변수 | 의미 |
|---|---|
| `selectedRouteId` | 선택 노선 |
| `selectedServiceDate` | 서울 운행 날짜 |
| `originStopId`, `destinationStopId` | 선택한 승차·하차 정거장 |
| `activeStopField` | origin 또는 destination. 마커 클릭으로 채울 입력칸 |
| `routeStops` | 그 날짜 패턴의 방문 목록 |
| `markersByStopId` | 마커 참조 |
| `mapStatus` | `loading` / `ready` / `failed` |
| `activeRequestId` | 날짜·노선 변경 시 이전 응답 폐기용 |

날짜·노선·정거장이 바뀌면 **이전 조회 응답을 요청 식별자로 버린다.** 취소된 요청이 늦게 끝나도 새 화면을 덮지 않는다.

## 8. 함수

| 함수 | 입력 → 결과 | 연결 |
|---|---|---|
| `loadRoutes` | — → 노선 목록. 노선 메타데이터 조회용. 전체 노선 페이지는 후순위 | `GET /routes` |
| `loadServiceCalendar` | 노선·기간 → 날짜 상태 | `GET /service-calendar` |
| `loadRouteStops` | 노선·**`serviceDate`(필수)**·선택 패턴/버전 → 방문 목록 | `GET /routes/{route_id}/stops` |
| `renderStopMarkers` | 정거장 → 마커 참조 | 카카오 Marker |
| `selectStop` | `stopId, activeStopField` → 해당 출발·도착 칸 동기화 | 양쪽 선택 후 후보 조회 |
| `getBoardingGuidance` | 정거장 → 승하차·결제 안내 | 로컬 표시 |
| `teardownMap` | — → 이벤트·참조 정리 | 화면 해제 |

## 10. 잠정 정거장과 조회 책임

04의 선문대 잠정 지점은 목록에 ‘선문대(휴일 표기·승차 위치 확인 필요)’로 표시한다. 아산캠퍼스 마커와 자동 합치지 않으며 관련 안내를 함께 제공한다. 확인되지 않은 좌표는 null이고 마커를 만들지 않는다.

05는 날짜에 적용되는 경로를 결정한다. 이 문서는 그 결과를 지도·목록에 표시하고 선택 상태를 관리한다. `GET /routes`와 날짜별 정거장 조회 API 정의를 화면마다 다르게 만들지 않는다. 노선·날짜 변경 시 후보 선택과 이전 구독도 정리하도록 12에 전달한다. 후보는 선택 노선으로 제한하고 다른 노선으로 자동 전환하지 않는다.

출발·도착 입력은 선택 노선의 정거장 목록에서 고른다. 일반 주소 검색이나 사용자의 현재 GPS 좌표를 출발지로 자동 해석하지 않는다. 서로 바꾸기 버튼은 두 값을 교환한 뒤 후보를 다시 검증하며 반대 방향 운행을 자동 생성하지 않는다. 네이버지도에서 본 입력 형태를 참고한 앱 자체 UI이며 지도 SDK 선택은 기존 카카오 우선안을 유지한다.
